# 首份演示体验蓝图

这是[已确认方向](../../docs/plans/character-chat-direction.md)的简短阅读视图，不是另一份需求权威；完整决定与修改记录以该文档为准。

## 想让用户看到什么

在一个聊天软件里，与生活在原作世界中的小说版和泉纱雾初次相识。她有自己的事情、情绪和意见，你们的交流能接续昨天。参照起点是第一卷开篇附近，具体依据待小说素材核对。

| 演示情景 | 观察重点 |
| --- | --- |
| 选择人物与故事起点 | 设置简明，人物依据可展开，不让后续剧情提前成为已知经历 |
| 初次聊天 | 消息语气与人物依据一致，彼此仍是刚认识的网友 |
| 隔天收到生活分享 | 事情有来由，主动消息不是机械打卡 |
| 接续前一天的话题 | 共同经历保持，前后的事件与态度有联系 |
| 表达一次不同意见 | 分歧源于人物性格、经历或关系，而非随机对抗 |

## 怎么判断

用户只需判断“人物感、连续性、交流自然度”。助手准备完整可观看的演示和说明，工程验证由助手负责；用户未反馈前不宣称体验通过。

## 演示需要透明的地方

标明预设台词、模拟时间和真正运行的能力。导入界面可作为流程示意，但未真实实现的小说分析必须说明；不能把剧情脚本冒充后台独立生活。先准备素材和选择原型实现边界，再开始制作。

原创角色的直接设定/问答双入口是确认的总体需求，首个演示不同时加入第二个角色流程。语音、图片及具体生活引擎方案仍待后续研究或原型反馈。
