# 下一阶段待决：一个有后果的生活与分享闭环

2026-09-27，**建议方案，尚未批准或实施**。S104持久聊天已交付，仍有过长、重复和无充分依据的过去细节等表达风险。完整产品还缺真实运行的生活和主动分享；S102明确排除了这两项新用途，不能从200次额度批准推断已允许。

## 建议用户批准的首个范围

先在独立试验分支验证同一纱雾定义，保留现有聊天及身份。只做一个小型创作项目：形成一份绘画构图文字方案，尝试一次有理由的修改，比较版本，再决定保留、重做或暂缓。留下实际可对比的文字方案与事件记录；不声称已经生成图片或完成原作剧情中的作品，不自动推进直播、身份揭露或关系重大节点。

人物提出想法，Python检查活动阶段、既有版本、允许修改与提交结果；只有成功提交的新事件才能成为此后的近况。模型/网络失败是系统故障，不伪装成角色创作受挫。以同一项目的前后变化检验生活，不用随机每天一条近况替代。

首期仅在应用开启时推进，可暂停；默认现实1分钟给虚构1分钟推进额度，遇到决策边界才调用模型，关闭后不补算。这是试验限制，不修改最终离线生活目标。验收可明确标注手动推进的虚构时间，不能冒充实时经过。

生活独立子限额每天最多6次决策调用＋2次分享表达，均计入现有200次总账（当前剩133），不是每天必须花完。暂停/没变化为0次；普通聊天继续最多2次/轮。无后台系统服务、系统通知或额外总额度。

主动分享只显示在应用内：先有成功事件，再决定是否愿意向初识对象透露；每天最多2条新话题，不是配额。用户未回复时不连续开新话题、不催促，不由等待时长生成关系恶化。关闭主动分享不停止生活，暂停生活停止新事件，两个控制分别有效。

## 新数据用途（此次真正需要确认的部分）

目的地继续`https://api.deepseek.com/chat/completions`、`deepseek-flash`，复用已有Windows凭据slot；仍不更换Provider。新增输入只涉及当前分支已提交的一个活动状态、当前文字方案和最多一个相关事件概要，用于提议下一步、普通聊天解释近况及选择/表达一次应用内分享。身份、人格和相关起点资料继续沿已有最小投影。

生活决策/主动分享不读取用户聊天原话，只接本地已验证的“已有交流/是否允许主动联系”有限布尔前景。用户主动聊天仍受既有最多2轮/4000字符和关闭开关控制；不会把此窗口自动授权给生活规划。原书引文、证据/数据库ID、其他身份、草稿、时间戳、推理和key不进入新增输入。

首次开发实测至多24次调用、遇技术失败停止，不自动重试；同样计入133余量。阶段配置与精确字段/示例在实现任务书中封闭核验，不能借本建议扩大到长期人格重写、自由造人物、全剧情模拟或外部行动。若机制需要超出上述范围，应先给具体差异，不默认为已批准。

## 设计依据、取舍与验收

复核[既有生活机制研究](../research/2026-09-24-life-mechanisms-review.md)的Concordia尝试/结算分责、近未来按需计划、ink条件后果、EMA事件意义；本次定向检索[Generative Agents官方仓库](https://github.com/joonspk-research/generative_agents)仍展示步进与模拟保存机制。借用事件与恢复思路，不复制双服务、源码key、高频tick或额外checkpoint。没有引入代码/依赖，许可与维护新增成本为零；不是把论文模型当人物有意识的证据。

EMA只提供“同一受阻可能有不同应对”的设计类比，不把情绪数值当真实性。实际检验：同一项目能跨三次推进/重启保持版本与结果；重复唤醒只成立一次；前置条件缺失不伪造完成；模型故障不变成故事事实；关闭/未回/频率限制可靠；用户能追问同一变化而非另编过去。自然度、人物感另由体验判断。

建议先批准上述有限生活/应用内分享试验。系统后台通知、离线补算、把试验能力升级到现有已聊天分支的版本兼容/数据处理，均另作具体方案，不在此包中隐含实施。
