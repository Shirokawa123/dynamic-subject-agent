# 角色聊天产品方向记录

最后更新：2026-09-19。状态：需求澄清中，首轮世界与关系入口已确认，整体规格未完成。

这是当前重新对齐产品方向的连续记录。已实现行为仍以PRODUCT/ARCHITECTURE及验收报告核实；本记录中的未来体验不能被说成已经实现，也不自动授权新的数据外发或迁移。整体方向对齐后再同步正式产品定义。

## 为什么重新对齐

用户明确说：“主要是我不是很想体验，感觉和我想象的差距很大”。因此下一步不是要求用户先测试dogfood-s51，也不是优先升级旧身份。此前工程闭环、测试数量和本地任务保存没有证明核心聊天体验符合用户期待。

用户原始愿景（原话）：

> 我原本想象的是类似一个聊天软件一样的，就像是和网友一样交流，对面虽然是虚拟的但是很有真实感，他也有自己的生活，也会和我分享他的喜怒哀乐和他自己做的事情，然后我希望能直接导入epub之类的文本文件和直接的动漫视频文件就能分析创建人物，还有自己的原创角色也能制作。

据此确认的目标：以聊天软件为主要体验；虚拟人物有可信的性格、生活连续性和情绪来由，能分享自己做的事情；希望通过EPUB等文本、动漫视频建角，并支持原创角色。导入先后顺序、具体技术路线和自动分析边界尚未确认。

## 已确认的决定

来源：本会话用户先说明“主要延续原作世界……但是要是能自己选择的”，随后对助手Q1–Q3建议回答“我觉得你的建议都对”。以下逐项对应，不扩展为其他未问问题的批准。

| 编号 | 决定 | 范围与含义 |
| --- | --- | --- |
| C1 | 世界模式可选，首版优先延续原作世界 | 进入新世界/不同人生也保留为后续方向；不能把原作模式做成唯一不可选路线。 |
| C2 | 用户可选择原作起始时间点 | 如某卷或某集之后；该时间点之后的剧情不自动成为角色已经历、已知的事情。具体选择界面和材料不足的处理未定。 |
| C3 | 默认保留原作世界、性格与既往经历，从起点允许分支 | 用户互动可以影响此后的选择和走向；另外提供严格遵循原剧情的模式。具体冲突规则尚未讨论。 |
| C4 | 首版中用户保持现实身份，角色生活在原作世界 | 双方通过一个双方都知道存在的聊天渠道相识，体验接近网友交流；不是默认把用户写成原作世界中的人物。渠道细节未定。 |

“世界在哪里”和“剧情能否分支”是两个独立选择：原作世界内也可以产生不同剧情；不能把分支模式误记成必须进入新世界。

## 讨论方式与记录要求

用户询问是否仍应采用Grill Me和Wayfinder，还是可以直接尝试。助手建议先澄清核心体验，再整理决策路线，遇到难以描述的体验时用原型辅助讨论；用户已参与首轮澄清。当前还没有建立完整Wayfinder地图，也没有宣布全部方向达成一致。

用户担心以前在GPT-5.5期间回答过许多问题却被遗忘，要求本地持续记录。每轮明确答复落盘，区分用户确认、助手建议和未决问题；后续开工先读本文。已确认问题不重新提问，除非出现具体冲突或用户主动修改。修改决定时保留日期、原因及被替代内容。

技术事实和可行性由助手调查，不让用户回答可以从仓库或官方资料查明的事实。当前不要求用户先体验旧成品来证明需求。

## 下一轮可讨论的问题（尚无答案）

1. 角色的生活如何推进：离线期间持续模拟、再次打开时补算，还是主要随互动推进？用户对时间和因果连续性的期待是什么？
2. 角色如何联系用户：只在打开聊天时分享，还是允许主动发消息/通知？频率、打扰控制和不回复时的行为未定。
3. 原作人物导入的首个具体使用案例、版本/时间线冲突和提取依据如何呈现？尚未选作品或文件。

后续再讨论：跨世界渠道的设定、关系起点与发展、情绪和自主选择的边界、原创角色的创作方式、严格剧情与分支之间的冲突处理、体验原型的通过标准。

这些是待澄清项，不是助手代替用户作出的决定。EPUB优先于视频、先制作一个原创角色演示等曾是助手建议，用户没有逐项确认其开发顺序。

## 与当前工程的关系

dogfood-s51是可复用的身份、记忆、状态和可靠持久化基础，不是此愿景已经完成的证据。旧文档中生活模拟/主动消息等冻结项与新愿景存在待解决的产品范围差异；当前仅进行需求设计，不越过旧授权直接实施。不可逆迁移、新credential用途、新Provider数据用途仍需具体授权。
