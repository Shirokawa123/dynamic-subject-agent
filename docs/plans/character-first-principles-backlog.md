# 角色聊天：从必要条件推导待办

本计划取代“发现一句不对→补一句提示/问句”的推进主线。用户要的是对面像一个知道自己是谁、有自己处境与意愿的人。目标不是声称意识或完整模拟人脑，也不是永不出错；是在明确资料和故事阶段内，能持续形成有依据、连贯且有分寸的交流。

这是待实施计划；不把术语、流程图或既有测试数量当成能力已完成。已确认需求见[方向记录](character-chat-direction.md)，运行不变量仍以ARCHITECTURE为准。

## 推导依据

1. **输出受可用表示限制。** 没有构建的人生、关系和知识，无法靠要求模型“更像人物”稳定地表达出来；预训练印象也不能替代当前阶段的可追溯依据。
2. **世界事实不等于角色所知。** 必须区分事件发生、角色获知、叙述者揭示和双方当前共享的信息；角色也可能有来源支持的误解或不确定。
3. **知道不等于愿意说。** 披露取决于关系、话题和意愿。缺少资料、不知情、记不清与不愿透露，不能都靠一句否认表现。
4. **交流是有所关注的行动。** 只给百科资料仍会形成问答机器；角色还需要当时处境、正在关注的事和开始交流的理由，才能接话、提出观点或选择话题。
5. **连续性需要已成立的状态。** 角色过去、共同聊天和新生活经历不能相互冒充。模型刚说过的故事不会自动成为发生过的事，两轮文本窗口也不等于长期相处。
6. **结构正确与人物体验必须分别验证。** 不泄露数据、JSON合法、能显示页面都必要，但无法证明角色认识自己、能自然交往；观察到某一句改善也不能证明一般问题已解决。

这些原则并未决定数据库、检索库或模型调用次数；技术方案应由下面的具体用户结果倒推。

## 统一待办与依赖

所有事项当前均未完成。以下为能力工作包，不同时开多个执行切片；每次只从一个可验收的纵向结果开工。

### F0 — 明确覆盖范围与验收问题

- 结果：定义“起点自我知识足够”的具体含义，避免以无限读书或几个答对的名字收口。
- 工作：按身份/生平、重要关系、工作与作品、能力与局限、价值与偏好、关注与目标、当前处境、世界常识与不确定性列覆盖表。每项标记已核对、未分析、冲突、起点不适用；明确哪些是基础缺口，哪些允许保留未知。
- 验收：已知的关键本人身份和前史不能漏；未知有范围，不以臆造填空。用于开发的已见例子与保留情景分开，覆盖改写、否定、跨话题与错误前提；不新建无关测试框架。
- 依赖：无。与F1迭代，不要求先穷尽全部长尾。

### F1 — 建立人物资料的语义与证据层

- 结果：从用户提供的多卷资料形成可追溯的人物相关事件、关系、作品及行为材料，超出少量手选绘画段落。
- 工作：区分人物/别名、叙述者/发言者、事件参与者、事件发生时间、获知时间、来源位置与资料版本；主线与IF分开，处理后卷回溯、不同译名、矛盾和缺失。先做完整结构覆盖再按人物和起点相关性深入，不把所有出现的文字都当目标角色自述。
- 验收：每个候选能回答“是谁的什么信息、何时成立、谁知道、依据在哪”；可纠错并保留版本。多卷分析覆盖与未处理部分明确展示，不能将结构扫描说成语义完成。
- 依赖：F0。任何模型分析先准备实际样本、最小外发及成本预算，再请求具体批准。

### F2 — 构建连贯的人物自我认识

- 结果：角色能从同一套自我认识回答生平、关系、工作、偏好与处境问题，而不是每道题临时拼背景。
- 工作：把F1材料组织成相互关联的本人经历、重要人物关系、角色能力、作品/职责、在意的事情与有依据的判断倾向；区分客观资料和角色自身理解。保留矛盾/不确定，不把少数行为推成永恒人格，不自动改写人格。
- 验收：换话题、换问法仍使用同一主体视角；不会知道笔名却不知道相应职业，也不会把另一个人的经历说成自己的。证据充分与认识覆盖都须检查；不是增加字段数量就算完成。
- 依赖：F1。先明确表示与更新职责，再选存储/索引；不预设必须知识图谱、向量库或长提示。

### F3 — 形成所选起点的知情与处境

- 结果：同一人物放在不同故事阶段，能正确区分已经历、已知、误解/未知以及尚未发生的内容。
- 工作：结合事件时间和获知时间筛选；后文揭示的早期背景可以进入，未来成长不能提前进入。明确起点的工作/关系状态、当前关注与环境；助手新增开场情境单独标注为用户采用的分支前提，不冒充原作。
- 验收：核心自我知识不因防剧透而被抹空；也不会提前认出尚未识别的人物身份。每条关键包含/排除有理由，无法确定的项清楚保留。
- 依赖：F2，并反馈F1补证据。

### F4 — 建立双方共同清楚的相识情境

- 结果：用户和角色都知道为什么能够联系、看见哪些资料、为何愿意回应，不必靠用户临场编前景。
- 工作：采用用户提出的社交软件按兴趣推荐联系人→用户主动私信的方向。明确页面公开信息、推荐理由、角色当时使用入口的目的及各自信息差；保持跨世界、初识和原作世界设定。
- 验收：双方对渠道和来信原因不矛盾；推荐不等于亲密，不默认公开所有隐私，也不假造用户看过哪些作品。愿意聊同一兴趣不等于欠用户持续回复。
- 依赖：可与F1–F3的设计并行，最终需F3的起点处境；具体情境中的新增事实需与原作背景分开确认。

### F5 — 让对话按意义使用人物知识并决定披露

- 结果：普通自由表达能唤起相关认识，并适当地回答、澄清或保留；核心本人知识不依赖正则命中。
- 工作：区分稳定核心、当前处境/关注、按需细节、实际共同聊天和用户当轮声称。先判适用/知情，再判关联和分享；允许不知道但不无故否认已知事实。来源未选中不等于角色不知道；用户未告知也不等于用户不可能知道。
- 验收：跨领域改写、转述、反问、错误前提、保密请求均有合理结果；不会自动接受用户断言，也不会拒绝与已核实背景一致的提及。有限失败必须显式，不假装“已理解全部”。
- 依赖：F3、F4。调研成熟项目的分层人物上下文与检索机制，比较能否复用；现有正则保留为明确控制语法或测试入口，不继续扩成开放聊天主引擎。

### F6 — 从处境与交流意图形成表达

- 结果：角色能接住邀请、选择小话题、表达意见、保留秘密或暂不聊，有一致的理由而不是固定冷淡模板。
- 工作：用当前关注、关系与话题确定回应方向，再形成自然语言；当下观点不必伪装成曾经做过，谨慎不需要每句否认。辨别说话者和知情边界，检查无依据的事件、习惯与心理解释；再决定是否需要额外模型任务或本地约束，不先承诺某种方案有效。
- 验收：用户表示“都可以”时能自行提出具体话题；无需虚构近期活动来撑场面。保持角色意见但不随机对抗、不无条件讨好、不连续把交流负担推给用户。知情/披露/不确定在行为上可区分。
- 依赖：F5。与F0的保留情景反复核对，不以某个禁句不再出现代替一般能力。

### F7 — 让共同经历保持连续

- 结果：新身份下聊天与获准的状态跨话题、跨会话/重启仍可接续；用户不用反复介绍双方已经知道的事。
- 工作：复用唯一Timeline/Publication与恢复能力，把实际互动、约定、身份来源与角色的既往背景区分；记忆选择与披露保留来源。两轮原话窗口只是表达上下文，不承担长期认识的全部职责。
- 验收：共同经历不凭空产生、不因摘要遗漏被否认；错误回复不能覆盖事实。重启保持身份隔离，撤回/删除策略与授权范围明确。不得事后收集或迁移此前约定不保存的自由聊天。
- 依赖：F3及F5的表示契约，进入小成品前完成最小可靠接续；新身份的保存行为先在切片和产品中明确；涉及新增外发或旧数据迁移时按既有规则取得批准。

### F8 — 在上述基础上推进角色生活与分享

- 结果：角色有能说明来由、能够接续的新日常，以及有理由分享的内容；不是每次聊天临时编一段经历。
- 工作：从关注/目标和世界条件提出事件，校验后经唯一写入路径成立；把事件发生、是否愿意分享、频率控制和实际投递分开。落实已有暂停/重大节点/每天最多两次新话题要求。
- 验收：用户离线不等于某件事已发生；重复启动不重复发生/投递；未回复不催促。生活可先有限，但前后不能自相矛盾。
- 依赖：F3、F6、F7。模型用途、时间机制和重大节点等未决项到具体可审方案时集中确认。

## 下一个小成品如何收口

**目标是“拥有起点自我知识和明确相识前景的基础角色聊天版”。** 先完成F0–F6及F7的最小可靠接续，不要求先完成所有动画导入、生活模拟和通知。知识完整度指覆盖上述关键维度并显式表达缺口，不承诺对全套小说任意细节全知。

交付前由助手验证：本人基本知识和关键关系不缺失；阶段边界可解释；普通改写不依赖菜单；相识前提双方一致；可以主动选择一个话题；回复不把无依据细节当经历；连续性与数据边界成立。仍有已知核心失败就如实标明，不命名为验收完成。用户只需自愿评价相处感觉，不承担一轮轮工程用例。

执行切片建议（是结果划分，不是一次性启动）：

1. **可审阅的起点人物模型**：先落地F0/F1/F2/F3的一条完整资料路径，给出关键维度覆盖、人物关联和时间判断；F4整理开场卡。没有真实语义覆盖前不再让用户试聊。
2. **自由表达下使用同一人物认识**：F5/F6接入新角色路径，运行保留情景与自然对话验收，比较真实改善，而不是扩大固定问句表。
3. **可以隔天接续的基础聊天版**：完成F7最小闭环并交付主聊天页，随后再展开F8生活与主动分享。

单个结果过大时可拆实现步骤，但步骤不冒充新的用户成品。每张实际任务书写明其对上述结果的贡献、明确范围和收口证据。

## 现在暂停的推进方式

- 不把补笔名、书名、一个习惯或一句提示单独作为下一主切片。
- 不继续扩写_MESSAGE_TOPICS来模拟开放话题理解；旧有限语法仍用于明确控制/检查，不急着删除。
- 不围绕同几条已经见过的消息反复调参并用它们宣布通过。
- 不用哈希核验、JSON成功、测试数量、页面可打开替代自我知识与体验验收。
- 不先扩大每日生活/主动消息，再让虚构经历掩盖人物基础缺失。
- 不推倒已验证的身份隔离、Facade、ModelGateway和单一Timeline，也不未经比较引入新框架。

## 工作与授权边界

用户已授权常规规划、实现和验证持续推进到小成品或真正选择点。已明确的自我知识要求和社交推荐方向不再重复提问。助手负责技术调研、方案与可审阅样本；新资料模型分析、外发字段/用途、预算与不可逆迁移仍按既有规则在具体方案完成后确认。新保存行为须明确，不追溯收集已承诺不保存的自由聊天；不为普通可逆的本地实现额外设置审批。规划不自动扩大既往已消费的真实调用额度。

下一执行起点为F0/F1：先制作资料覆盖与语义表示方案，并用跨领域、跨卷且与起点相关的真实材料验证一条完整路径。它需回答是否足以形成角色自己的认识，而不是是否又找到了几条可聊天的句子。
