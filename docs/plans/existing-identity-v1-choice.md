# 已有身份如何使用v1：待决定范围

当前没有迁移或读取正式身份。dogfood-s51在新建隔离身份完成任务与文本保存的闭环验证；旧身份仍使用原运行contract和Timeline schema，聊天、历史及原有能力保持。

## 选择一：保留旧身份，用新身份体验候选版

无旧数据修改。通过已有来源建角流程建立一个新身份并切换；新身份从新的经历开始，具备明确任务和逐次确认保存。可随时切回旧身份，但新旧记忆、关系、目标和任务互不继承。

这是当前已实现、可直接使用的路径。适合先验证日常体验；代价是不能把旧角色的连续经历带入新功能。

## 选择二：准备保留经历的旧身份升级

要让同一身份及原历史继续使用新执行权限，需专门迁移任务书与可验证升级程序。计划只针对用户明确选定的身份，不批量升级全部角色；不新建第二canonical store，不重新生成历史，不新增Provider投影。

执行前必须完成：停服与无在途操作核对、覆盖registry/Studio/Host/Timeline的本地一致备份及摘要、在合成同结构数据上的升级与恢复演练、旧行/历史摘要完全一致验证、Host权限与Timeline schema协调切换及故障恢复。当前没有这个迁移程序，不能直接改两个版本号假装升级完成。

新版本产生新经历后，旧程序不能解释新的effect记录；直接恢复升级前备份会失去之后的经历。因此要先决定升级窗口和回退方式，不能承诺任意时刻无损降级。任何真实迁移须在具体目标、备份位置、验收与回退方案明确后再执行。

依据AGENTS.md：“删除、不可逆数据迁移、新 credential 用途、新 provider 数据用途必须先获用户批准。”当前A路线授权没有包含旧身份不可逆迁移。此文件是下一项产品选择，未授权也未启动正式数据升级。
