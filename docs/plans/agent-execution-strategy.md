# 开发协作

2026-10-29精简。当前目标与范围从[current](../slices/current.md)读取，常驻规则在[AGENTS](../../AGENTS.md)。本页只处理需要协作时的安排；旧S109校准表、固定实验预算与当时未决项见[历史快照](agent-execution-strategy.history-2026-10-29.md)，不作为新任务前置。

## 何时协作

主窗口能直接完成的工作直接做。用户要求并行，或任务确有可独立交付的部分且当前工具/指令允许时，再委派；多人协作不作为每阶段的必经流程。涉及同一状态、权限、恢复或紧密依赖的修改，由一个实施所有者贯通。

需要独立复核时，给出具体风险、稳定差异和验收问题。没有固定人数、固定模型岗位或项目级思考档上限，工具实际支持与会话更高优先级限制优先。模型共识不能替代证据，复核通过不要求制造问题。

## 怎样交接

简报说明用户结果、必要依据、有效边界、写入目标、验收和交还条件即可。每个写入目标及共享运行资源同一时刻只有一个所有者；主窗口负责跨职责决定、集成、必要核验与交付，不同时重复子任务。

任务完成即交还；范围变化、证据冲突或连续尝试没有新信息时，交回主窗口重判。等待仅用于当前步骤确实依赖结果时。

## 怎样收口

按实际产物与证据接纳，区分工程行为和人物体验。达到本次验收后交付，只有新改动、失败或明确疑点才扩大检查。协作本身不新增报告体系、实验配额或模型评测任务。

开发协作不扩大产品数据、Provider、凭据、后台通知、删除或迁移用途。模型、档位、用量不可得时如实说明，不为填记录扫描无关会话。
