## 先定结果，再选择协作方式

主窗口从唯一current任务书确定本轮用户结果、已见失败、有效边界和验收，指出当前最需要解决的未知或实现工作。已有信息足够时直接动手；需要补证据时只调查影响当前决定的问题。

| 任务结构 | 合理安排 | 交还与接纳 |
| --- | --- | --- |
| 范围小、步骤明确，或下一步紧接前一步 | 主窗口直接完成 | 产物和必要检查足以说明完成 |
| 独立资料、不同故障假设或可分开的调查方向 | 按需委派调查者，可并行 | 返回直接证据、结论和未解问题，主窗口据此选路 |
| 能独立交付的功能结果，接口与写入归属明确 | 指定实施所有者；写入与运行资源互不干扰时可并行 | 交付完整改动、验证和影响，不按函数或文件数量拆成果 |
| 强耦合的状态、权限、恢复或跨层语义 | 一个实施所有者贯通相关层；可配独立调查 | 主窗口处理跨职责取舍，减少来回交接 |
| 稳定产物存在高后果风险、争议，或用户要求复核 | 新上下文的复核者检查指定风险与完整结果 | 按证据报告问题或通过，主窗口决定修复与接纳 |

这些是职责，主窗口可以兼任调查和实施，不要求四个代理或固定执行顺序。团队人数由可独立推进的工作决定，受当前宿主容量约束；没有项目级固定人数。追加成员前说清他能独立交还什么，收拢团队时保留尚未完成的工作。

## 模型和思考档按次选择

用户授权主窗口为开发任务自主选择可用模型与受支持思考档。调查、实施、复核都可以使用任何合适的可用模型；也可使用相同模型的新上下文，不将角色名称当作模型能力证明。主窗口本身按当前客户端设置运行，委派参数不代表主窗口设置已经改变。

选择时先判断：

- **任务难点与错误后果。** 复杂语义、重要取舍、状态恢复或难以验证的结果，可以直接选择更可靠的模型及更深入推理，无需先让较弱组合失败一遍。
- **可验证性与等待成本。** 边界清楚、结果可快速核对的工作，可优先响应快、总成本合适的组合；不能以省token代替用户结果。
- **实际表现与缺失信息。** 优先参考类似任务的完成质量、返工和耗时；证据不足时沿用当前合适组合，并标记选择理由，而不编造性能排行榜。

需要调整时先定位瓶颈：缺依据就补依据，工具不可用就处理工具问题，职责强耦合就收拢任务；能力不足时可提高模型或思考档，也可因耗时、成本和实际表现更换模型或调整档位。不同模型并不保证独立正确，最高档也不保证解决规格冲突。范围内选择与调整自主完成，实际资源不足时再提出具体取舍。

## 派发与写入归属

给子任务一份足够执行的短简报，内容按需要取用：

> 完整用户结果及本子任务的贡献；要回答的问题或交付物；必要来源和已确认决定；依赖、写入目标与共享资源；验收及交还条件；模型/思考选择理由；返回产物、证据和未决项。

相关文件、失败现象和既往方案是线索，未经核实的根因标为假设。调查/复核通常从新上下文开始；实施确需近期决定时带最少必要历史。信息不足时定向补读，不用省上下文掩盖关键约束。

每个写入目标同一时刻只有一个所有者，端口、临时目录和其他共享运行资源也需区分。主窗口可修改其他目标或处理未决问题，不同时重做已委派的任务。子任务范围变化或需额外协作时交回主窗口协调；接口变化先确认依赖，再继续下游写入。

复核稳定的差异或明确冻结的部分；同一目标仍在修改时先结束修改再作最终判断。复核者可以追查必要代码和证据，返回明确问题或通过；没有问题数量配额，不因偏好不同就要求重构。

## 主窗口持续负责整体

主窗口保留整体目标、当前假设、跨模块决定和验收证据。在选路线、跨职责合同变化、完整结果收口时，核对局部工作是否改善整体体验。新证据推翻诊断或补丁持续增加却没有改善时，调整路线；日常局部动作无需重审全仓。

接纳以原始需求、实际产物和可复核证据为准，不仅看实施者总结或代理间共识。人物产品变更分别报告工程行为与实际交流体验；模拟测试不冒充真实人物验收。工程协作/文档任务按自身结果验收，不强行运行产品情景。

主窗口看关键差异和风险证据，负责集成、必要检查、提交与推送。只有新改动、失败或明确未解疑点才扩大或重复验证。子任务验收已满足即可交还；跨范围、证据冲突或连续尝试没有新信息时交回主窗口重判，停止空转的子循环，同时继续可独立推进的总任务。

反馈按对象与阶段更新：用户目标、长期硬边界、当前阶段安排和助手假设分开。暂缓某实现不取消对应能力；被否定的方案只有相关前提改变才重新讨论。需要用户决定时，先完成独立准备，再提交具体可审选项。

## 工具与授权边界

以本轮真实工具说明核对模型、档位、并发、上下文继承和隔离方式，不在此缓存固定模型名单或平台人数。上游文档中的配置/接口不一定存在于当前宿主；当前共享目录就按共享写入处理。全历史继承与显式选模不兼容时，使用必要简报或有限历史，不宣称未生效的配置。

续接已有任务时使用能触发执行的工具；补充消息不等于唤醒已结束的工作者。只有依赖结果阻塞当前关键步骤时才等待，期间先做不重复的独立工作。

开发协作授权不扩大产品Provider、凭据、私人资料、后台通知、删除或迁移用途。既有数据与操作边界仍有效。本策略不安装外部编排框架或固定模型profile；若以后需要引入，先核对实际收益、配置优先级、许可和数据范围。

## 在真实任务中校准

在现有收尾记录中简记：为何直接做或委派、模型/档位（可得时）、完成时间、协调与返工原因、必要验证、最终用户结果。用量或实际模型不可得就标未知，避免从请求参数推断账单或生效设置；不额外扫描无关会话日志。

观察协调成本、缺陷和交付速度：独立工作积压可增加并行，重复调查或合并负担过大就收拢，难验证的错误集中出现就提高能力或增加针对性复核。策略修改依据实际任务证据，不为测模型而重复实施生产功能，不承诺尚未测得的节省比例。

协作与指令规则更新本身不新增产品用途或额度。S109实施准备与已授权开发按current推进；待审48次真实实验、云端方案及数据/凭据用途分别按其具体授权处理。
