## 1. 项目到底为了什么

让用户通过聊天，长期认识一个来自作品或原创设定的虚拟人物。她有稳定而不僵硬的自我认识，有自己的关注、能力和生活进展；双方的相处会影响此后的理解与选择。用户回来时，可以延续同一个人的同一段人生。

“真实感”在这个产品里首先是**连续且有理由的行为**。漂亮措辞、信息量、情绪标签都不足以成立。建议用六个可以被反例推翻的问题判断：

1. **她是谁？** 换个话题、换种问法、重启后，工作、重要关系、能力和经历仍一致吗？
2. **她怎么知道？** 能区分亲历、别人告诉她、推测、未知和暂不愿说吗？
3. **她为什么这样选？** 相同外部请求下，已有关注与能力是否实际改变她的选择？
4. **发生过什么？** 昨天的尝试、失败、完成有记录，还是今天临时编一段解释？
5. **我们经历了什么？** 能记得说过什么、误解如何澄清、哪些话题尚未结束，而非只存用户标签吗？
6. **我能掌控体验吗？** 建角、纠错、暂停、通知和失败状态能否理解，使用是否自然且负担可接受？

不把机器具有意识或人类情感作为前提。目标是可以观察和纠错的虚构人物行为。也不要求先模拟整个世界：首版只需维护足够支撑这个人物生活的世界事实。

### 从目标推导必要结构

- 长期是同一个人，要求**固定起点定义＋有因果次序的新增经历**。
- 角色视野有限，要求**世界成立、角色获知、角色理解、对用户披露分开**。
- 有自己的生活，要求**目标/活动产生后果**，不依赖用户每次发问才补写过去。
- 相处会改变未来，要求**交谈影响有限的认识与选择**，同时不覆盖原作与已提交历史。
- 生成模型会错，要求**建议与成立分开、失败可恢复、证据可回查**。
- 普通用户要能使用，要求复杂度藏在内部；正常产品流程只围绕创建、聊天、生活控制和纠错。

若一项状态或Module不能改变上述行为、降低已见错误或减少维护成本，就不因名称像心理机制而增加它。

## 3. 选择什么总体路线

| 路线 | 优点 | 本项目取舍 |
| --- | --- | --- |
| 角色卡＋长上下文 | 最快得到自然对话，成本和实现易理解 | 保留为正式对照基线；不能单独保证新事件、时序和重启一致 |
| 角色卡＋通用检索 | 资料量可扩展 | 借其取材方法；仍需角色知情、定义版本、事件权威，检索命中不是事实批准 |
| 专属微调模型 | 可能改善风格和特定角色知识 | 后置。训练不能自动解决新分支事实、用户记忆或投递一致性 |
| 全社会多Agent模拟 | 世界可能更丰富 | 首版不采用。调用成本、多个事实源及失控叙事会遮住主要用户结果 |
| 全剧情脚本 | 可重现、可审 | 用于测试替身或严格剧情节点；不足以支撑开放交流 |
| **受控事件运行＋人物视图＋开放表达** | 能让自然语言和可靠连续状态共存 | 推荐。先小世界、少活动、单写者；语义正确性和趣味性仍须实测 |

推荐采用本地Python单体。UI经ApplicationFacade进入；模型经ModelGateway；原作资产、作者草稿与运行权威按职责分开。无需先引入Agent框架、图数据库、队列集群或多个心理Agent。索引和摘要可以增加，但必须可从权威记录重建。

**可以保留底座，必须重做新人物的运行契约。** 不把新生活伪装成用户命令，也不把旧六能力拼接器改名为人物大脑。新角色使用明确版本的contract与新身份；旧contract继续可读和可运行，不进行隐式升级。

## 4. 什么是事实，什么只是表达

### 最小权威模型

| 内容 | 为什么需要 | 谁能让它成立 |
| --- | --- | --- |
| 来源资产及定位 | 核对原作，修正提取错误 | 用户提供的文件及内容指纹；索引不是真值 |
| 封存人物定义 | 稳定起点、能力、重要经历、关系、知情与世界约束 | 作者流程审核并显式freeze；复用Studio版本和IdentityAuthority |
| 分支事件记录 | 记录此后尝试、结果、观察、真实交谈及投递意图 | 当前身份的Runtime经规则裁决与原子Publication |
| 当前活动、短期评价、关系认识 | 解释下一步选择，并跨重启保持相同 | 确定性部分从事件派生；模型提出且被接纳的非确定性变化必须随依据提交 |
| 人物视图、摘要和检索索引 | 在预算内使用前述资料 | 只读/可重建，绑定定义版本和Timeline head；不得独立改写事实 |

最少保留`定义版本、分支/身份、事件/请求标识、逻辑次序、触发依据、类型化变化`。这不是提前建一大堆表；每种变化随真实功能加入。只在一句话中出现却没有依据的事情，不因模型重复说了三次就变成事实。

### 必须拆开的四种命题

- 世界中发生了A。
- 角色观察到/被告知A，或错误地相信A。
- 角色认为A对自己的某个目标意味着什么。
- 角色已经向用户表达A。

例如用户说“你哥哥就是那位作者”，首先成立的是**用户作出了这个断言**。是否可信、是否进一步核实、是否改变角色信念需要独立依据；不能直接建立“角色已确认真实身份”。系统作者索引知道两个别名同人，也不得把索引合并结果直接转成角色识别。

用户评价可以引起她困惑或反驳；不必等待用户批准每个虚构反应。程序校验的是可接受的变化范围与依据，不是用规则证明自然语言中的所有心理因果。自动长期人格重写/Reflection继续不启用。

### 允许创造到哪一层

| 内容 | 允许方式 |
| --- | --- |
| 对已知事情的说法、当前观点、问题、比喻 | 模型可开放生成；不自动生成新的持久人格事实 |
| 新的日常活动、安排与结果 | 先提出类型化变化，按活动/世界契约批准后才成为经历 |
| 新的重要人物、过去经历、身份、能力或重大剧情 | 不得作为聊天润色夹带；转作者修订或明确分支事件流程 |
| 反事实、建议和计划 | 保持可能/打算的语义；未执行不进已完成历史 |
| 未知细节 | 可以不说、澄清或表达不确定；不能统一演成角色失忆或冷淡 |

这比“任何没在原文中的句子都禁止”更可用，也比“只要很像她就算发生”更可控。

## 5. 建角：从一堆文本到能影响行为的人物

### 作者流程

1. **接收与解析。** 核对文件、版本、卷章顺序，保持段落/场景定位；原作主线、IF、动画等不自动混在一起。复用现有来源核验，补通用目录解析和进度恢复。
2. **场景理解。** 候选识别人、别名、说话者、叙述视角、事件与获知途径。场景保留否定、反讽、撤回、回忆与前后文；不能只抽一句引文就下结论。
3. **人物组织。** 稳定核心、重要经历脉络、具体能力/限制、关系视角、当前关注和表达习惯分别形成可回溯摘要。先保存证据，再做解释；同一经历可支持不同侧面而不复制成多个事实。
4. **起点审查。** 分别查事件何时发生、她何时知道、当时是否已有这种关系/能力；未来资料仅作作者侧参考。未抽到、未知、未获知三者分开。
5. **解决影响运行的缺口。** 优先解决本人是谁、做什么、为什么在意、目前处境、重要关系、秘密和能力边界。细枝末节不足可有限开聊；关键冲突未解不能以漂亮摘要盖过。
6. **形成简明确认。** 用户看一页人物描述、起点与影响最大的待定项，可展开出处纠错；系统/助手负责核查工作。模型置信度不当作真实性概率，也不把全量人工标注交给用户。
7. **封存和建分支。** 定义版本绑定新身份和初始世界/相识条件；同一定义可建多个隔离分支。后续修正形成新版本，不回写已发生历史。

**纠错必须能影响后续体验。** 仅新建定义版本而让旧分支持续答错不算完成。先分析修正影响了哪些现有事件、知情与回复：默认可创建使用修正版的新分支；若要沿原分支继续，须设计显式、向前生效的定义修正事件和兼容规则，保留旧版依据及历史原文，不能演成角色突然获得原本不该知道的秘密。现有freeze机制尚未提供这一契约，列为P2待设计；未获准或无法保持一致时只提供新分支，不静默迁移。

原创建角从步骤3进入，用户设定是作者依据，助手新增部分明确标记。视频以后增加前置Adapter：字幕/ASR、时间码、镜头、说话者/人物和画面事件对齐，再进入同一流程。

正式聊天读取已核验并封存的定义与必要材料快照，校验其版本和完整性；不应每轮重新解压全书、跑抽取或要求原文件始终在原路径。原文用于作者修订和按需回查，来源后来移走影响的是重新核查能力，不自动抹除已封存且完整的人物知识。当前预览每次核验来源适用于作者实验；P2需落实运行快照契约及失效规则。

### 人物认识的组织与使用

**常驻核心**是简短的连贯认识：身份、能力和限制、核心关系、重要经历为何重要、当前阶段与关键未知。每段能回查依据；不是30条命题改成30个字段，也不是一串性格形容词。

**经历单元**保留场景、参与者、前因、选择、结果、获知途径以及有依据的意义。**按需资料**包括作品、细节和相似交流情景。**当前处境/共同经历**来自分支，不塞回原作。

装配顺序固定为：

`身份/版本/权限/起点与知情过滤 → 核心与当前活动 → 当前消息及未完话题查相关经历 → 补必要前因 → 去重与预算 → 精确请求`

简单查询可用本地别名、主题、时间索引；语义转述需实测更强检索。中文两字名、别名和“为什么重要”必须进入检索验收，不能假定默认FTS或向量天然解决。初期直接排序候选列表即可，不需要图数据库。核心太大要回到作者整理，不静默截断关键身份。

每条被选资料都应回答“为什么这轮需要它”。对于开放邀请，候选来自她的当前活动/关注和双方未完话题，不依赖用户输入一个作品关键词。隐私程度、长期重要性、当轮相关性是三个独立判断。

## 6. 一轮聊天怎样真正运行

```mermaid
flowchart LR
  U[用户消息] --> F[Facade: 身份与请求]
  F --> S[读取已提交快照]
  S --> V[装配人物视图]
  V --> P[模型提出交流行动与回复]
  P --> J[裁决变化与核对表达]
  J --> T[原子提交交谈及获准变化]
  T --> UI[按消息标识展示]
  T --> S
```

1. 绑定身份、定义版本、预期head和幂等键；重发相同请求读原结果。新消息不能在旧人物页面的迟到响应中串入。
2. 读取核心、当前活动、已披露/未完话题、预算内完整对话轮与相关经历。控制/撤回先限制活跃使用，再做检索；错误回复仍是“曾经说过”，不是可信人物事实。
3. 模型根据交流目的提出一个简短行动：回答、澄清、保留、提出话题或表达不同意见；可同时提出有限认识变化，携带本次请求局部依据标签。标签映射本地权威ID，内部数据库ID不外发。不要求输出私有思维链。
4. Python检查依据范围、权限、时间、状态转移、当前head和预算；有限关系变化必须引用具体交谈，不因轮数增长自动亲密。语义核对另看输出是否添入未经允许的具体经历/秘密。
5. 如变化被拒绝且回复依赖该变化，回复也不能照发。普通无状态轮先试一次联合生成；依赖裁决结果的轮先裁决再表达，或在明确预算内修复一次。持续失败显示系统错误/允许重试，不把网络故障演成角色在生气。
6. 接纳的交谈及同轮合法变化通过同一Publication提交，随后展示最终消息。崩溃后从canonical消息恢复，不能让UI先存成功、Timeline里却没有。

**程序能保证的**是身份、引用、许可、结构、状态转移和原子性。**程序不能凭正则保证的**是所有自由台词忠实、动机自然或角色还原。语义检查模型也可能同错；因此需要已知反例、独立情景和诚实的失败统计。不能为了零表面风险把所有回复变成“不知道”。

语义核对先比较两个可实现方案：A在单次候选中给出简短事实/经历陈述及依据标签，观点另标，程序核对许可范围；B另用一次有界核对，读取候选及同一授权依据，检查正文夹带的新经历、身份和秘密。A可能漏报自己补造的陈述，B可能误判或与生成器同错；两者都测漏拦、误拒、最终有效回应及总调用成本。资料支持不足时可缩小回答；核对器失败则是系统无法确认，不伪装成角色不知道。新核对用途先准备精确投影再批准，不能绕过用途边界。

### 共同记忆和关系

完整交谈轮保留在现有canonical存储；查询用可重建话题/事件索引。常驻对话状态只需当前话题、未解决的问题、近期约定及披露依据。关系初期使用带理由的有限描述/规则，例如某话题已愿意聊、某次误解已澄清；不先引入精确“好感72.3”。

“用户说过”“双方理解一致”“已答应”“已履行”分别处理。她可以重新考虑自己的看法，新的认识带触发事件向前追加；旧事实不被覆盖。停止使用/逻辑遗忘也不得借摘要或检索恢复外发，物理删除依现有治理另行处理。

## 7. 生活系统：用小世界产生真的后果

### 世界最少包含什么

当前时间与场景、正在进行的项目/活动、必要资源与能力约束、已发生事件、少量外部条件和不可越过的剧情节点。没有进入模型的宇宙细节无需全部模拟；但只要某项结果影响此后的行动或聊天，就必须有明确归属。

旁人物初期可由受控世界事件表示，例如一个已定义的消息到达。不能随意伪造亲人评价来解释角色心情；新旁人物活动同样受人物、关系、时间和视角限制。若以后实际体验表明缺少他人自主性才增加限定的旁人物运行，而非从多Agent社会起步。

### 最小行动契约

每类活动定义：可操作对象、开始前提、持续/推进条件、允许的结果、可能阻碍及不可改变的事实。首个领域按角色真实能力选择创作活动。内部可以是几种操作：开始、继续、检查、修改、暂缓、完成；不同人物的数据和目标不同，转换机制共用。

`关注/未完成事项 → 选择可行动作 → 核验前提 → 开始或推进 → 形成允许结果 → 提交事件 → 获知/短期评价 → 下次选择`

模型可以选“继续构图还是先检查配色”及具体表达；不能直接宣告“拿了奖”“获得新委托”“突然不认识自己的职业”。规则生成确定性事实；对有限随机结果，记录选定结果及依据，重放不重新抽样。一个第二LLM世界裁判可辅助语义判断，但不能代替有限活动契约和唯一写者。

活动不是每次必须成功。返工、改变方法、暂时无进展和休息可以是有效结果；无前提的失败也不应为制造戏剧随机加入。待验证的设计假设是：项目跨日推进、选择产生代价、过去问题留下后果，能够比每天换一句随机近况更有趣；现有研究不保证长期效果。

### 一个完整演算（合成例，不是纱雾原作事实）

假设一个有绘画经验的原创人物已明确想完成一张插画，并有未完成草稿D。D至少记录创作意图、候选方案和待检查条件；若没有真实图像，只能核对这些结构化条件或记录人物自己的满意判断，不能客观测出透视或构图质量。

| 步骤 | 输入及决定 | 成立的结果 |
| --- | --- | --- |
| 1 想做 | 已有项目和她在意的表现目标；提议下一步检查构图 | 只建立计划，不声称已经检查 |
| 2 开始 | D存在、无冲突活动、有可用时段 | 提交开始事件；同一活动重复推进先检查进度 |
| 3 检查 | 比较D的方案与已建模创作意图，发现一个明确条件尚未满足，或接纳她对当前方案不满意的评价 | 提交条件核对/主观评价及返工事件；不伪装视觉测量，也不补出新委托人或获奖经历 |
| 4 应对 | 她仍在意原目标，允许选择修改或暂缓 | 接纳短期失望/专注等有理由反应及下一意图，不改写永久人格 |
| 5 进展 | 获准继续且完成必要阶段 | 提交草稿修订/阶段完成；“改好一部分”不能说成整幅已发表 |
| 6 分享 | 昨天与用户聊过类似取舍，事件可分享且未发过 | 生成有关这次选择的消息，校验后提交消息及投递意图 |
| 7 接续 | 重启后用户问“最后选哪个？” | 从D的同一事件链回答；不重新掷骰产生另一个结果 |

对目标人物，活动和评价必须从其资料和起点校准，不能重演已失败的“专业画师像新手一样画杯子、靠用户指导成长”。初版不假装真的生成了图片文件；如以后提供真实画作，生成与保存还需独立effect结果。

### 情绪怎样有作用

采用事件评价的工程类比：发生了什么→影响哪个关注→符合/妨碍目标、是否可控→当下反应和应对。最初只存会改变行为的短期评价，如更想独处、愿意分享成果、需要继续检查；无需先有复杂情绪坐标。

必须做对照：删去评价后选择/分享毫无差别，说明它只是装饰，应简化；同一事件换成不相关目标就不应产生同等反应。心理学是形成假设的工具，不提供角色有真实心理体验的证据。

## 8. 离线时间、重大剧情和主动联系

**推荐有界按需推进，与后台推进共用一套语义。** 现实经过的时间只产生允许推进的额度；具体生活仍由活动转换产生。应用退出时可以不执行，重新打开按已提交游标补算；若需要离线期间真实通知，则必须有获准运行的后台进程。两种模式不能混称。

补算只推进到下一个值得记录的活动变化，不逐秒调用模型。设置每次最大步骤/调用/追赶范围；超过范围只走规则允许的平常时段压缩或停下，不造出一串没有计算的具体经历。耗尽预算保留待推进状态，不能谎称生活已完成。

新聊天到来时，先结束当前原子推进并至多做约定的有界补算，再将聊天落在**当前已结算的逻辑前沿**。未用完的现实推进额度留给其后的生活；不得日后把新事件追溯插到这轮聊天之前，改掉它当时的依据。世界滞后应明确显示，不能一边聊天称已经到今天，一边以后补写昨天决定过什么。head检查解决并发，逻辑前沿规则解决因果次序，两者都需要。

逻辑时间、现实提交时间、聊天时间分别保存。查询“昨晚”按场景解释；不能把补算的提交时刻伪装成当时已经送达消息。暂停不累计未来爆发式补算，恢复策略在设置中明示。忙碌允许短回复/稍后接续，避免用人为长等待制造真实感。

**重大节点必须在结果发生前识别。** 初期由剧情图/事件类别显式标注身份揭露、关系重大变化、迁居、重大损失等节点；纯模型临时判“重大”不够。默认保护模式走到门槛即暂缓该转换。门槛前还有不改变前提的日常活动可继续；没有可行活动就暂停世界时钟并显示等待参与，不无限生产“又过一天”绕过门槛。这是对尚未定细节的建议，须在真实运行方案中确认。

严格原剧情模式要有独立节点前提。用户影响使下一节点不再成立时，明确给出继续严格约束或新建分支的选择；不强行写角色失忆，也不偷偷把相冲突两条剧情同时当真。首个可用版先实现已选默认分支，严格模式完成前显示不可用。

### 分享和投递是独立决定

1. 是否有已提交、尚未分享、对她有意义的事件？
2. 是否愿意对这个人讲，是否与双方话题有关？不默认最私密的才最重要。
3. 现在是否适合联系？暂停、免打扰、联系开关、未回复状态和次数限制先检查。
4. 生成消息后是否忠实于事件？无新事实时也可以保持安静。
5. 消息、可投递意图与新话题额度预留原子关联；实际dispatch前按最新暂停/许可、免打扰及用户已知内容再裁决。排队期间已通过聊天告知的结果不另开重复话题；本地消息按canonical ID去重。通知失败不回滚已经成立的生活事件。

额度的预留、消费与取消都属于同一权威，不能由两个worker同时读“剩1次”各发一次；跨日待发意图需按实际发送日重新核对。尚未开始的投递可取消，已经交给外部渠道的发送只尽力停止，不声称暂停能够撤回已送达内容。主动联系开关、生活暂停和通知免打扰分别生效，不把关闭通知误解成删除生活事件。

默认每天最多两次新话题沿用用户选择。建议按用户配置时区的现实日累计，而不是加速世界日；这是实施建议。上限不是任务，换日不触发催促；未回复时抑制重复同题/追问，不把沉默解释成背叛或关系下降。

本地聊天消息可按ID去重；系统通知在“已发出但回执未落盘”时可能送达未知，不能普遍承诺exactly-once。状态unknown须有明确恢复策略，避免盲目重发。OS通知许可和后台运行属于后续具体授权方案。

## 9. 架构要怎样划分才有意义

以下是逻辑职责，按现有Python包逐步深化；不要求六个服务、六个Agent或六次模型调用。

| Module/内部Interface示意 | 隐藏的复杂度及输出 | 状态权威、失败与现有落点 |
| --- | --- | --- |
| **CharacterAuthoring**：导入/审阅/封存 | 解析、证据、冲突、人物组织、起点和版本；输出可审人物定义 | 作者状态由Studio持有，来源坏不能假通过；适配source_evidence/evidence_model/Studio |
| **CharacterPerspective**：按情境prepare | 知情过滤、核心与经历选择、共同记忆、披露约束、预算；输出可追溯视图 | 只读已封存定义与Runtime快照；缺核心和无相关细节区分；深化chat_context |
| **Conversation**：对一次消息propose | 交际目的、当前立场、话题与整体表达；输出候选及有限变化 | 无写权；格式/语义失败分开。替代新角色沿用旧Composite的路线，复用Gateway |
| **Life**：对推进额度propose | 有限活动、世界条件、结果与短期评价；输出类型化事件候选 | 无写权；暂停/无事可做为NoOp，来源/状态不一致FailedClosed；首个真实新能力 |
| **Runtime**：提交一种明确command | 幂等、冻结依据、版本/权限、唯一裁决与Publication、恢复 | 唯一分支写者；复用SubjectRuntime/Timeline/IdentityAuthority，逐项新增contract |
| **Delivery**：交付已提交消息 | 排队、通知渠道、回执和重放；输出可理解送达状态 | 意图/回执属于同一运行权威，Adapter不得私建聊天真值库；复用effect原则而非保存权限 |

外部仍只有ApplicationFacade，生产装配仍是open_local_product。正式UI不调用“先预览证据→再组上下文→再造请求”来拼一轮聊天；这些内部步骤通过一个用户操作完成，诊断在辅助视图。保留lab作开发工具；不再每个DTO都永久增加产品入口。

最重要的契约是跨Module传递同一个定义版本、分支head与局部依据映射。并发生活与聊天必须串行裁决或因head过期重建请求，不能以旧状态直接提交。未来非确定性状态先提交再复用，摘要缓存失效只重建摘要，不重生成已经成立的经历。

### 错误的影响应局部化

- 非关键索引损坏：从权威数据重建/采用有界只读回退，不声称人物忘记人生。
- 来源原文件暂缺但封存定义完整：保留既有聊天，来源回查显示不可用；作者修订不能跳过缺失的核验。
- 核心定义或Timeline完整性损坏：阻止依赖它的生成/提交，显示系统问题。
- 生活模型失败：不产生事件；已有聊天可在已提交状态上继续。
- 一项关系变化不获准：独立且不依赖该变化的回复可继续；不能把它的回执作为已发生事实。
- Provider超时或预算耗尽：保留已提交结果和请求状态，不无限重试。
- 通知失败：保留可在应用内读取的消息和送达状态，不重复制造生活事件。

## 10. 数据、调用与成本如何受控

拟议投影按用途拆开，**均不是现有授权的自动扩展**：

| 用途 | 最小需要的数据 | 明确排除 |
| --- | --- | --- |
| 来源抽取 | 获准场景文本、局部人物/版本提示和任务规则 | 正式聊天、用户私人记录、运行状态 |
| 人物回复 | 已审核心、相关经历摘要、当前处境、最少共同对话、当前消息和披露条件 | 全书、作者未来知识、整个Timeline、其他身份、原始内部ID |
| 生活提议 | 角色关注/能力、活动快照、当前可用世界条件与规则 | 无关用户聊天、全部原作、其他Domain库存 |
| 分享表达 | 已成立事件、分享范围及必要共同话题 | 无关生活/历史与不允许披露的详情 |
| 本地裁决/恢复/投递 | 权威ID、状态与已提交结果 | 不需要新模型调用 |

默认先让一次普通无状态聊天只需一次生成；需要语义核对或裁决后重写时显式计入额外成本。不要为“检索、情绪、人格、关系、计划”各设必调模型。质量是否值得额外调用必须用同预算对照决定。

拟议预算由`每轮输入/输出上限、每轮总尝试、每次生活推进步骤、每天后台调用/费用`共同限制。token用实际usage计，字符数不能冒充token；单日成本按各调用输入/输出token乘所用模型现行单价计算。具体价格、额度和时区在真实调用方案确定，本轮不假报费用。

本地优先表示数据权威在本地，不表示现有远程Provider能够断网推理。新原文、摘要、历史、生活用途和embedding外发都需精确样例与具体批准；现有credential只维持既有用途。

## 11. 怎么证明它真的比现在好

验收同时看工程正确性和人物体验；只使用既有行为测试、能力回归和不变量测试的组织方式，不另建一套测试名目。

### 先做能推翻设计的对照

- **资料实验**：同一模型/预算/材料，比较平铺原案、连贯核心、核心加经历检索。交换材料顺序，测试短名字、隐喻转述、跨主题与起点秘密。全量更好则保留全量；分层不是预定胜者。
- **行为实验**：固定事件与消息，改变有证据的当前关注/关系/能力约束，观察选择是否合理改变；再固定核心跨话题，观察身份是否保持。结构只改变解释字段、不改变行为，视为没有收益。
- **生活实验**：相同已提交快照，分别实时小步与离线同等额度推进；比较约束和可恢复性。若结果含随机性则固定已选结果/种子，不要求不同采样文本逐字相同。
- **整体实验**：人物创建→初识→一次自己的项目进展→次日主动分享→延续共同话题→合理不同意→重启继续。必须连着跑，不能把不同重置会话里的最佳回复拼成成功演示。
- **自动建角实验**：至少一份未参与开发的获准小说样本，从文件解析完整走到简明确认人物定义，记录关键知识遗漏、知情误归属、冲突发现与人工修正量；覆盖晚揭示早发生及别名已消歧但角色尚未识破。人工修到能聊和系统自动提取得好须分别报告。

### 冻结的内容场景至少覆盖

本人职业与经历、动机解释、亲历过去、非亲历但已获知、过去却不知情、未来剧情、保密而非否认、用户错误前提、开放邀请、不同意见、误解修复、知识更新、撤回限制、长期接续、生活失败、未回复不催。原作知识依据由助手预先核对，不能让生成器给自己出题并判满分。

把开发例和未见验收例分开；第一次失败保留，不用无限重试挑好样本。结构错误、错取材、越界知情、添造经历、表达生硬分别记录。模型评判可辅助，但不能单独宣布人物感达标；助手核对事实，用户自愿判断完整体验，不承担逐轮工程排错。

### 建议阶段门槛（待实施时固定样本与预算）

- 身份串用、未提交冒充成功、未获准外发、重复成立同一事件：冻结验收中0次；这是测试结果要求，不是对开放世界的数学保证。
- 起点关键秘密、职业否认、虚构重大经历：任一明确反例阻止阶段达标。
- 普通回应还需正向有效：能回答/推进合适话题，不能靠全部拒答过关。逐场景列通过率、拒答率与盲评胜/平/负，不只给综合分。
- 自然度与人物感至少相对简单基线不退步；若复杂方案改善不明确而成本更高，先简化。
- 成本、P50/P95响应时间、首次成功率、每轮调用数、人工修正次数一起报告。后续设产品预算目标前先有真实测量，不在本文虚构性能保证。

## 12. 从现状走到成品的实施顺序

阶段是可体验结果，不是新增文件数量。本轮研究完成后，不自动执行真实调用或后台能力。

| 阶段 | 具体交付与现有落点 | 收口结果/停止条件 |
| --- | --- | --- |
| **P1：认识确实进入行为** | 将已审连贯核心、经历关联、按需资料接进现有Facade候选路径；保留平铺基线；完成输入预览和语义对照方案 | 离线能验证选择与边界；获准真实对照后才可称人物改善。若取材正确仍总编造，先查表达机制，不继续堆字段 |
| **P2：同一个人物持续相处** | Studio定义版本→新身份；正式角色chat contract→单Timeline提交/恢复；交际与披露、未完话题和有限关系认识；设计建角后纠错影响分析/新分支契约 | 连续聊天、误解修复和重启成立；脱离固定S59/S72作品路径。沿原分支应用修订仍需兼容与明确批准，不能只创建版本就声称旧分支已纠错 |
| **P3：自己的一个项目与一次分享** | 一个有限活动域、逻辑时间输入、前提/结果、短期评价、分享决策和本地收件箱；测试时钟与真实时钟同契约 | 从已建意图到进展/失败，再到消息和次日接续；重启无重造/重发。不能拿预写台词验收生活 |
| **P4：完整小说/原创小成品** | 通用导入、自动候选质量、简明确认与纠错；聊天UI、暂停/速度/通知控制、明确费用与故障状态 | 五情景连续体验及未参与开发小说的自动建角实验通过，人工修正量单列；助手先检查工程和事实，再交用户看感觉 |
| **P5：扩大世界和输入** | 严格剧情完整冲突处理、视频短场景到长素材、更多活动/旁人物、其他世界与媒介 | 每个扩展先重审资料和权利/成本，按实际体验缺口决定，不以全社会模拟替代单人物完成度 |

P1仍是高优先待办，但不再把“人物知识系统穷尽”当作P2/P3前提。先用小而可靠的人物包贯通相处与生活，才能发现真正需要什么资料；完整自动建角在P4达标，不能永远由助手手写替代C16。

### 下一张实现任务书建议

围绕一个结果：“换话题仍是同一个人，能按本轮需要取用有来由的经历”。从当前审核包生成核心/经历/细节视图，替换prepare_context的全量复制，保留每段依据与原基线；通过Facade观察精确输入，准备未见情景与外发样例。先完成离线准备，再对具体真实投影/预算集中确认。不得把离线选择成功当作自然聊天已经成功。

## 13. 后续真正需要用户决策的事

已经确认的人物、起点、初识、兴趣推荐和总体体验不重问。Module命名、索引实验、内部数据结构由助手负责。

到相关阶段再带具体可审方案集中确认：新人物/历史/原文/生活投影外发的目的地、样例和预算；后台运行与通知许可；时间比例、暂停恢复和重大节点停等细则；严格剧情冲突的实际选项；如需不可逆迁移或物理删除则单独处理。

当前推荐路线的核心判断是：**先让少量可信认识和一个有后果的生活项目参与连续交流，再按测得的失败扩大能力。** 它仍可能被试验推翻，尤其是自动人物提取、自由表达忠实度、长期关系和有限活动趣味性；这些是后续需要解决的具体问题，不用新增抽象名称掩盖。
