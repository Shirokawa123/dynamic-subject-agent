## 结论

推荐保留可靠基础，在新的角色聊天运行路径中重组核心职责，并通过隔离原型验证后逐步接回正式产品。既不直接把小说塞进旧回复路径，也没有证据支持推倒全部重写或立即迁入另一套Agent框架。

变化不只在界面。旧主流程以用户消息触发能力处理，新目标还需要角色自己的虚构生活事件、按阶段筛选的人物知识，以及与生活推进分离的主动联系策略。先把这些契约说清楚，再做可看、可核对的原型。

## 产品定义应怎样调整（草案）

建议以以下描述替代旧v1的任务中心收口目标：本地优先的角色聊天软件，让用户与有来源、处于明确故事阶段的虚拟人物长期交流；人物拥有可接续的虚构生活、心情与自主意见，主动联系受用户控制。

首个体验以小说版和泉纱雾、第一卷开篇附近、初次相识为参照，采用已确认五情景和三项体验标准。文件保存、状态面板和测试数量不再作为核心体验完成的替代指标。原创角色双入口、可选世界/剧情模式保留为总体目标，不要求首次原型同时全部实现。

现有[PRODUCT](../PRODUCT.md)仍将Lifeworld/主动消息等列为冻结项。这是旧运行范围与新体验要求的待同步差异，不应通过偷偷放松旧规则处理。正式新路径实施前，应把目标体验、各阶段非目标和模型数据用途同步成一致的PRODUCT/ARCHITECTURE/DECISIONS。

## 拟议的职责划分

以下是设计候选，不是新增生产Module已经存在。

1. **小说来源与人物资料**：管理卷章、版本、人物别名与证据范围。来源资产和可重建索引不具有独立修改运行事实的权威。
2. **起点/当前人物上下文**：区分原作资料、当时适用背景、分支中已发生事件和实际共同聊天。先按时间/知情/权限筛选，再检索相关内容。模型读到的范围仍须明确批准。
3. **生活推进**：基于故事时间及当前分支提出事件，校验前置条件、来源和冲突后提交。虚构事件明确属于分支，不宣称现实世界发生过，也不改写原作与真实用户消息。
4. **聊天编排**：处理用户消息，结合已经成立的人物依据与经历生成自然表达。知识、记忆、关系和状态是支撑，不是必须逐项朗读的回复段落。
5. **分享与消息投递**：生活事件成立→有分享意愿且可分享→允许新话题→投递。每天两次是投递上限，不驱动系统凑生活或凑消息；暂停、未回复和投递去重在本地策略处理。

ApplicationFacade仍是产品唯一业务Interface；SubjectRuntime/Timeline仍拥有运行事实的唯一写权。原型中的“推进一天”是明确操作，不能伪装成生产时钟已在后台跑了一天。真实投递要区分已生成、待投递和已送达，借鉴既有effect恢复经验但不冒用文本保存授权。

## 成熟设计的复用与取舍

本地代码核对同时由research子代理查了三组一手资料。Context7检索fetch failed，按技能回退官方文档；没有下载代码或引入依赖。

- [Generative Agents原论文](https://arxiv.org/html/2304.03442v2)与[官方实现](https://github.com/joonspk-research/generative_agents)：有时间的经历记录、相关性/近期性/重要性检索、规划及模拟步恢复，能启发避免重复编造同一天。论文也报告记忆遗漏、编造和语气过正式，不能证明原作还原或长期稳定。只借鉴事件/检索思路，不照搬Reflection、自由自治或其源码中保存key的做法。
- [LangGraph Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)与[Interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)：显式保存推进位置、暂停和恢复输入，恢复前的副作用需分离或幂等。优先复用现有Publication/Host恢复，不加入第二checkpoint权威。框架并不替我们定义重大节点或长期缺席阈值。
- [Letta旧版memory文档](https://docs.letta.com/v1-sdk/memory/archival-memory)：常驻上下文、按需资料检索和真实对话搜索的分责可参考。但相关性不证明人物知情，agent写入记忆不替代Python裁决；该页是V1 legacy概念参考，不据此采用新SDK。

这些来源没有直接提供满足C6/C15的完整主动联系策略；上面的生活→分享→投递分离，是结合需求与本地代码的设计推论。

| 独立五情景原型 | 有清晰标记的演示及可选交互 | 用户评价人物感/连续性/自然度；不依赖迁移正式身份，不声称脚本等于生活引擎 |
| 最小真实生活闭环 | 新输入/投影契约、一个可提交和恢复的虚构事件、基于该事件的分享 | 模型只提议；事件和消息去重；身份隔离；明确获准的模型用途；不丢弃旧不变量 |
| 接入正式聊天产品 | 新聊天主界面、资料管理、独立分享策略 | 将体验认可的行为逐步替换进入主线；兼容/迁移另有验证与授权 |

不能现在把这些阶段同时作为可执行切片。原型为了评判设计，可以先采用有限、透明的模拟；生产实现前则必须完成正式契约和数据用途的同步。旧测试继续守护保留的行为，新测试围绕新用户结果，不以旧927项全绿代替新体验验收。
