# 起点档案之后：离线上下文装配

2026-09-24，Slice-70整理出的下一实现方向，尚未执行。当前不需要用户重答愿景，也不应无限扩充原文来拖延对话接入。

## 已具备的起点基础

S70本地档案从同一核验视图组织本人身份/作品、生平链条、家庭/职业关系、具体能力限制、创作取舍与起点安排。九维全书覆盖仍partial，但已能支撑有限开放聊天的离线设计。原作全知不是启动条件；身份、职业、关系和处境不能缺席则是条件。

## 下一片可执行结果

经Facade预览一份可解释的角色对话上下文，不调用Provider、不输出伪装成真人聊天的固定回声。预览明确分区：

1. 核心本人背景：由已核验起点命题构成，跨话题仍存在，不依赖关键词才能想起自己是谁。
2. 相关经历与细节：保留时间/视角限定；初版可采用受控全量适用材料，而不是先自建语义检索。是否需要检索应由实际长度和效果决定。
3. 相识前景：按已确认的兴趣推荐→用户私信；账号公开信息、推荐理由和双方知情一致。新社交场景是产品分支设定，不写入原作证据。拟使用仅绘画/插画兴趣，不默认展示真名/年龄/住址/职业笔名关联。
4. 交流与披露约束：知道自己的工作不等于必须公开身份；未介绍过也不能推定用户不可能知道；拒答、澄清和未知分开。
5. 当轮消息与共同聊天：用户声称不变成角色经历，生成回复不变成人物事实；连续历史使用已有合法写入路径，不能另建权威聊天库。

起点当前安排是预告而非强制剧情时钟，不得让每一轮角色都永久处于“马上要直播”。首次相识的具体时间安放属于分支配置，应在可审预览中清楚列明，不能先声称双方已经实际见过或聊过。

## 进入真实聊天前的条件

- 明确最小外发摘要、字段、长度、用途和凭据使用，复用同一授权时不重复索取许可；新增范围要有具体预览。
- 固定完整核心不包含未纳入/后续知情事实。作者署名与哥哥关系不能通过实体标签或解释文字泄漏。
- 离线检查只验证选用边界，不声称人物表达通过。真实内容检验需覆盖陌生问法、错误前提、跨话题、保留隐私和开放邀请，不能只有笔名问答。
- 关系发展、真实生活生成和主动消息仍后置。当前工程下一步应解决知识如何持续用于交流，不再以新增若干引用单独冒充产品进展。
