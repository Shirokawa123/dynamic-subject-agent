## 推荐工作顺序

1. **确定可用接入点。** 核上游版本/依赖/许可、与本机build的适配；先准备不调用模型的检查。实际装入和启动时明确写入文件、自动配置与窗口影响，按已获授权范围操作。验收桥可连接、状态与游戏一致；开始/停止/自然结束须分别观察，不以HTTP成功替代游戏实际结果。并行查清新增文字输入/展示面板、剧情阶段读取是否有可维护接缝；结论不成立时先报告具体原因和替代路径，不无限逆向。
2. **建立梅莫莉的起点资料。** 按游戏文本与实际起点整理她的自我认识、说话方式、重要关系、魔法学习和当前处境；原文依据、助手解释、缺口分开。用户已明确全部通关，S159据52–55话形成通关后起点草案；继续通读关键节点、核对连贯性后再准备人物包，不能把全量文字外发视作已批准。资料整理仍由助手承担，不要求用户逐条人工标注。建立独立人物定义与相处记录，原身份/资料不转换。
3. **接一条可持续的交流路径。** 新增自由交流入口，复用Facade/既有持久聊天与恢复。建议首版保留游戏原剧情及进度的权威，自由交流围绕已成立事实与新增共同经历展开；原剧情是否允许生成分支另行决定。界面优先调查游戏内新增面板；若成本明显妨碍完整试用，再给出贴边窗口等具体替代方案，不预先把替代方案当用户已选择。
4. **接入有来源的共同学习事件。** 仅接当前功能需要的计时开始、停止/结束、休息及用户明确提供的交流内容；游戏仍拥有计时/剧情事实，我方通过有来源的观察形成共同经历。观察缺口保持未知，不从一个快照补造完整历史；完成一个番茄钟不等于任务已完成或知识已掌握。先准备精确未发送请求样例，再落实新增人物资料/学习事件的模型用途；游戏存档全文、未来剧情和无关文件不因“接入游戏”自动成为模型输入。
5. **交付实际学习试用。** 同一个人物、同一段相处走完“开工交流→真实专注→休息接话→关开恢复→下次继续”。只为查清具体失败做必要验证，工程检查与人物体验分列；不以模拟时间替代实际时段，不把预设台词当自由交流。

上述顺序用于收敛未知，不要求先把通用人物系统和全剧情机制全部建完。必要的工程与本地准备可在既有授权内推进，确有新增用途或运行边界时先做出准确、可审的材料，再集中处理。

## 职责与最小验收

- 游戏拥有原剧情、原生专注计时、画面与动作；角色系统拥有独立人物定义及我方实际提交的交流/共同经历。桥接只转换明确事实与操作，不让两边同时改写同一份权威状态。
- 模型只提议，Python裁决；RuntimeTimeline仍单写者/单canonical，Publication原子与恢复语义保持。仅计时状态变化不意味着允许模型创建人物经历或后台发消息。
- 接入可用：能稳定读状态、分清未连接/未知/失败；后续获准的原生操作与实际动画/计时/结算一致，原进度可继续使用。
- 人物成立：开放聊天符合已核梅莫莉，能区分她的世界、用户说过的话与系统实际观察；不借未解锁剧情回答。
- 相处连续：休息时可准确接续开工所聊；重启后保留同一人物和实际经历，观察丢失不补造事件。
- 日常可用：专注时不主动打断；暂停、失败、聊天与原剧情能理解。用户评价是否愿意继续使用、是否像梅莫莉，工程通过不代替该评价。

首个版本的成功是上述完整体验可用。学业成绩提升、广泛自主生活、任意动作控制和完整剧情改写不由该结果自动证明；仍按后续具体用户目标处理。
