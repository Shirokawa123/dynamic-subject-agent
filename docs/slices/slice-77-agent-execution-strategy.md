# Slice-77：开发协作的多模型Agent执行方案

2026-09-26。类型：研究与实践设计，不实现产品功能。

用户希望以Astra作为重大决策与整合主窗口，按任务分派Sol/Luna，偏好Sol high、Luna xhigh，并核查oil-oil team-mode等Skill以提高token利用率。

后续明确授权：“如果你有更好的模型安排方式就按照你的，并且给出原因”。据此采用按任务路由而非固定全体高档位；增加AGENTS简短入口以供后续执行，不安装全局配置。

## 范围与验收

- 核对官方Codex子agent、模型和计费文档，与当前会话实际工具能力对照。
- 只读审核team-mode的Skill、角色配置、用量统计与兼容性，不因研究请求自动安装或改全局配置。
- 给出最小团队、模型路由、上下文/文件所有权、升级/复核与成本测量的可执行建议，并以P1为例。
- 区分API费用、订阅配额和token数量；没有实测不宣称节省比例。
- 这是开发协作模式，不改产品内的角色运行架构，也不扩展项目Provider、凭据或私人数据用途。
- 文档检查、提交和推送后收口，恢复P1为下一实现方向。

研究方式：主助手核对官方资料；一个GPT-6 Luna xhigh子agent用独立短任务核查第三方Skill，仅只读、无进一步委派。其总结由主助手核对后采纳。

## 结果与收口

已形成[执行策略](../plans/agent-execution-strategy.md)，AGENTS增加简短按需入口。采用Luna medium调查、Luna high局部低风险工作、Sol high主要实现与重要复核，Astra保留取舍与接纳；xhigh按任务升级。已与当前4个总并发、无agent_type和直接模型覆盖能力对照。

主助手读官方子agent/模型/计费文档及第三方源码；一个Luna xhigh独立任务核查上游角色、固定提交与统计限制。仅任务派发按新配置实践，未取得可用于比较的总token/账单数据，不能宣称成本实验通过。未安装Skill/profile/哨兵、未读私人日志、未启动产品功能实现或Provider新用途。
