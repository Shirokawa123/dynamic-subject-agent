## 用户结果

当前消息已经提供可谈内容时，应用能承接或询问用户希望怎样继续，不默认要求已有长期记忆或封存资料。换题后再请求改写，应使用正确对象；无安全对象时澄清。此结果不等于自动创作、自动记忆或通用自然语言理解。

## 顺序与边界

1. 先沿真实组合路径建立红色复现，以 Slice-21 T5/T10 的“接下来是另一段虚构小故事：两个人在鸢尾桥道别。”为起点；区分模型原始回复、能力本地校验和最终组合，不先认定提示词问题。
2. 在现有能力本地表达/组合边界内修复已证实原因，不按每条验收台词增加白名单。不新建统一表达 Provider、第二聊天 store 或新 Domain。
3. Provider 字段、用途、历史窗口、调用预算与当前授权保持不变。诊断与对抗复查证实，模型把提供题材当作创作任务，本地不能由生成失败推断用户意图；仅在既有 Living Memory reply 提示内明确当前话题/已明确讨论/事实问题/创作的现有用途区分，其余 11 类请求保留全部现有 outbound 字节。若必须改变未获授权的数据用途或既有架构硬边界，停止实现并请求用户选择，不用降级验收掩盖。
4. 事实问答继续保留完整 sealed 来源上下文；未知不补造。当前虚构内容不当成角色/用户真实经历，表达修复不更改 Domain 裁决，不凭历史写 Memory/目标/关系/状态。
5. 不读取正式身份或旧救援数据。真实流程只使用新临时隔离身份及原创虚构输入，复用已有 DeepSeek credential 的原鉴权用途；新增短期历史仍只去获授权 LM reply，控制/更正/完整性规则保持。

## 最小验收

- 使用仓库已约定的 ApplicationFacade submit/wait/query 与生产组合测试表面；外部 Provider 可用固定返回建立快速可重复失败，真实验收不得替换或挑选模型结果。
- 普通当前内容与换题、明确创作、来源事实/未知问题分别保持适当行为，不用一条万能回复掩盖分支。
- 连续覆盖旧话题→新内容→改写/澄清→继续，包含旧 Memory 干扰、虚构/事实区分、遗忘后不回流，以及进程重启后的原文恢复。
- 保留 Slice-19 事实/活动与安全回退、Slice-21 指代/隐私/投影回归及五条永久不变量；不新增测试类别。
- 原始失败留证，相关先红后绿、全量测试、真实 Windows 浏览器 UI/DeepSeek/重启检查；按基线分别做 Standards/Spec 独立对抗审查后，commit/push。若仍不成立，保留未收口状态和具体原因。
