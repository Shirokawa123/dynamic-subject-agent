# Slice-105：有后果的创作生活与应用内分享

2026-09-27，基线911092f。用户在完整进度说明及有限生活用途方案后答复“那就继续推进吧”，接纳按该方案继续实施；不再重复申请同一范围。具体范围以[first-life-loop-review](../plans/first-life-loop-review.md)为准：独立试验分支、同一已批准纱雾定义、一个绘画构图文字项目、应用开启期间有限推进、应用内主动分享。同DeepSeek、现有共享200额度；实际余量开工读取，首次开发真实验收最多24次，首技术失败停止。后台系统通知、离线补算、旧身份迁移和长期人格重写不在本片。

## 用户结果与缺口

用户能看到同一创作方案经过提出、修改、保留/重做/暂缓，重启后版本和原因仍一致；向人物追问时引用本分支已提交变化。有值得分享的新后果时可收到一条应用内消息，未回复不重复催促；暂停生活和关闭分享分别有效。当前S104仅有聊天，没有生活事件与主动消息；不能把自由回复追认为活动发生。

## 开工与所有权

先核对既有Timeline/Runtime/Host输入、原子提交、冻结投影及共享预算，再形成研究和可审运行合同后实施。新schema/contract限新试验身份，原已聊天身份继续可读；不将生活伪装成用户发言，不另建生活事实真值库。ApplicationFacade唯一业务入口，production composition负责装配，Authority负责身份/Host准备，模型统一通过Gateway。每个源码目标同一时间一位写者。

主窗口负责决策、研究记录、docs/app及真实验收。Sol high先只读给可复用接线方案，批准技术方案后再单一所有者实施src/tests。独立Sol检查稳定差异和重大恢复/权限问题；不为了并行拆碎同一canonical修改。

## 验收

- 生活是明确系统输入，与用户对话分开；仅新合同可推进。相同请求/唤醒只提交一次，有原子崩溃恢复，不造第二条Timeline。
- 一个项目至少三次有内容变化的推进，版本、修改理由、保留/返工/暂缓结果可查看，聊天可接续；生成文字方案不冒称生成图片。
- 来源/人物知识不改；生活材料仅当前活动、当前文字方案与最多一个相关事件概要，无用户原话进入生活决策/主动分享。
- 暂停/无变化0调用，关闭应用不补算；历史关闭仍有效。每日最多6次生活决策+2次分享、共享总200、开发实测最多24，不因重启/新分支重置。
- 已有交流且允许联系才考虑分享；日上限2非配额、未回不连续开新话题、重启不重复；普通聊天已披露与待分享内容保持一致。
- 技术失败显示系统状态、不写成创作挫折；未知/不可用/无变化有区别。基础聊天旧contract继续通过适用回归。
