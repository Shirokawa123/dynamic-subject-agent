## 有限范围与授权

- 复用现有 capability-local expression/近期对话 seam；配文与写作命令支持有限直接句式及其风格限制，完整禁写/引用/过去转述/假设不是新增授权。保留既有明确假设创作句的原契约。
- 限字缩写仅支持直接“能/可以/请…缩到/缩短到/改短到 N 个字以内”类请求，N 为 1–99 的十进制或中文整数；正文按非空白 Unicode 字符计数，标点计入，剥离受控创作前缀与一对外引号。输出超限、原样重复或没有安全最近文本时诚实说明，不盲目截断、不增加重试调用。
- 仅缩窄原 LM reply 安全窗口至最近一个完整已提交对话，不向更早历史回找；最多两轮/4,000字符、控制/更正/遗忘/权限/完整性关闭规则不变。当前评论可与直接限字请求并存；涉及事实/活动或数据操作的独立问题不由限字规则吞掉。
- 不新增 Provider 字段、数据用途或调用次数；若真实表现需要，仅细化既有 LM reply 同用途提示，其余11类请求字节保持不变。不改持久状态、资料来源或原历史主文。
- Slice-23 遗忘和 Slice-24 事实保护是兼容性前提；不扩展统一表达层、Agency/effect、Reflection、Lifeworld、主动消息或正式身份。

## 验收顺序

1. 预先约定的 ApplicationFacade 行为 seam 上，原配文先红后绿；实际禁写/引用对照不放行模型 creative 标签。
2. 原限字请求先红后绿，验证最近对象、整数边界、超限/失败不冒充成功、合法状态仍独立；控制之后无历史不泄露旧内容。
3. 相关和全量测试；按 code-review 技能做独立 Standards/Spec 审查并处理具体反例。
4. 后台 production HTTP + 真实 DeepSeek 在新临时隔离根复验原体验顺序与对照，保存所有首轮失败；不操作焦点或输入法。文档记录有限范围和剩余问题，commit/push 后收口，不自动开启第四项。
