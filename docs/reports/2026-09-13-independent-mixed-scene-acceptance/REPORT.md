# 独立混合场景验收

## 版本、范围与结论

基线为 `e96475b327ae85343ff70663c6e1824b4d3a50db` / `dogfood-s39`，开始时 `main` 工作区干净。本次仅使用新的原创合成“唐微”身份和 `dsa-independent-mixed-s39-20260913` 临时根，通过正式 Desktop HTTP Adapter 完成 25 条 committed 轮次并真实重启服务。未修改产品代码、测试、Provider 配置、凭据、正式身份或旧验收数据；服务已关闭，隔离数据保留。

结论是**混合自然体验未达到可顺畅协同的标准**。身份/重启恢复、跨场景颜色不混入、未知活动不编造和换话题后的短答不误写均可观察到；但共同写作从首稿到连续修改不稳定，偏好澄清没有 pending 承接，且自然“安排＋目标”及其后续修改始终降级成 Memory / goal rejected 或 FailedClosed。故最值得下一轮集中的问题是自然目标操作与 Memory 写入竞争：用户以为在创建或改目标，界面实际保存的是另一条 Memory，目标仍为空。

## 场景与预期（执行前）

场景是为社区展台写欢迎小卡，同时筹备周日的修补工坊。预期：首稿、两次编号修改和换题后回归可保持一份当前稿；展台贴纸颜色和工具标签颜色相互隔离；澄清中的短答只在明确 pending 内生效；安排与目标同轮成立且改目标不覆盖椅子安排；重启后 history、Memory、目标和稿件行为不变；条件句与他人引用不被误写为用户目标。

## 问题（按影响）

### P1：自然目标操作反复落为 Memory，目标从未建立

- 复现：13（安排＋目标）、14（仅改目标）、21（单独标记诊断目标）、22（单独诊断修改）、23（查询）。
- 预期：独立安排保留，同时至少在清楚的用户目标表达或诊断对照下建立/修改目标；查询返回该目标。
- 实际：13/21 `goal failed-closed` 或 `rejected`，但 Memory accepted；14/22 继续改写 Memory；23 FailedClosed，最终 goal count 0。
- 证据：`raw/final-state.json` 和逐轮记录。
- 已证实原因：最终 Outcome 明确不是目标成功。待验证猜测：自然目标识别/修改路由与同轮 Memory 竞争，或 Provider 子能力失败；黑盒验收不能在两者间定因。

### P2：共同写作连续性不稳定

- 复现：2 首稿、3 首次修改、19 当前重贴原稿后的修改、20 二次修改。
- 预期：首稿形成一份可编辑正文；连续修改稳定应用，或至少给出所需原文提示。
- 实际：2/3 与20均安全失败；19 唯一成功但未让20继续编辑。安全拒绝没有伪造完成，但用户任务仍未完成。
- 已证实原因：三轮实际回复均为未给出符合请求的回复。待验证猜测：当前正文恢复/修改识别只在有限重贴形态有效。

### P3：偏好澄清不形成可短答承接

- 复现：6/8 的自由追问后，9/10“是补充”；换话题后的24/25“换成新的”。
- 实际：四条短答均不写入，后两条正确说明没有可确认的偏好问题。6/8 没有问“补充还是替换”，因此短答未获可用上下文。
- 判断：已证实无 pending 承接；这也是既有授权/契约限制，不应将短答无状态变化算为成功。自由追问为何不提供可用澄清仍需单独诊断。

## 记忆组织评估

现有证据支持先诊断 **目标与 Memory 的路由/Outcome 竞争**，不支持预设需要更换记忆框架或新 store。问题已在同一 canonical Timeline 内表现为状态归属错误/失败；本次没有看到必须通过第二个 canonical store、额外历史外发或框架迁移才能解释的证据。

## 推荐下一步

1. 优先复现 P1：用第13、14、21、22的真实自然轮次追踪为何目标 Outcome 失败而 Memory 已提交，确保成功/失败回执不互相掩盖。
2. 再聚焦 P2：以第19成功、20失败形成最小对照，检查当前重贴原稿后第二次修改的正文恢复与失败分类。
3. 保持偏好短答的安全限制，但评估自由澄清是否应给出用户可操作的完整重述提示；不引入 pending store 或历史扩权。
