## 最终行为

MemoryControl 本地识别唯一完整姓名/昵称记录，或 exact「完整原文」的一条 active Memory；Domain 按同一 admitted message 与完整性明确的本地库存独立校验，原子追加撤回结果。Timeline 从既有 Outcome 派生 `forgotten`，不建立新 store、不改写历史。成功台词与说明读取最终 Outcome，UI 不再把停用记忆说成新建记录，旧卡片明确标注“已停用·历史保留”。

本地目标唯一性与 Provider 最近 20 条 active 投影分离；100 条历史读取窗口无法证明完整时拒绝猜测。纯保留请求为 NoOp，引用不触发操作，混合不确定/不支持的物理删除命令不执行。未提交控制按该操作冻结前缀定位并限制披露，不把暂缓外发说成实际停用；读失败、空清单与真实未决控制分开说明。清单及缺失姓名的有限查询本地回答，不用“没有当前记录”推断“用户从未提供过”。

正常 Provider 字段、提示和用途未改。明确控制/清单/缺失姓名查询减少 Memory 请求，其余能力走既有路径；没有新增每轮调用。已停用记录不进 active 投影，历史修订链不复活旧值；用户重新直接提供可建立独立新记录。

## 实际后台过程与失败保留

全程通过新临时隔离根、生产 DesktopState/ApplicationFacade 和真实 DeepSeek；没有 UI、焦点或输入法操作，没有读取正式身份。使用现有 Credential Manager 的原鉴权用途。完整结果见 [final-live.json](final-live.json)，首轮问题见 [first-live.json](first-live.json)，只含虚构姓名和偏好；[egress.json](egress.json) 为 ModelGateway 的投影元数据，不是网络抓包或密钥/认证头记录。

原姓名在初次停用后没有进入后续 Memory/近期文本投影；用户 T11 重新提供后可合法出现在新记录投影，再次停用后不回流。不能把全部同字字符串永久禁用当成逻辑遗忘。清单查询和普通 Provider 召回分别验证，不混算。统计观察不证明每一种故障网络路径，未知/中断由 Interface 故障回归验证。

## 明确限制

- 只处理本身份 Living Memory 的单条逻辑撤回，不删除 Timeline/数据库，不自动跨 Knowledge、目标或身份设定清除相同词语；确认台词说明历史保留。
- 姓名/昵称须是可识别的完整记录，或使用 exact 原文。多候选、混合约束、物理删除请求、不完整库存不猜测。达到 100 条历史窗口会保守拒绝本地完整性判断，不把 Provider 20 条当全部库存。
- 未知或混合的 pending 控制可能持续限制 Memory/历史披露；限制不是成功停用，也没有自动解封治理流程。明确已定位的未提交目标可重试逻辑遗忘，其他记录保留；不支持情形需进一步明确处理，不偷偷恢复外发。
- 非闭集的自由回忆表达仍由模型生成，不保证任意措辞都能避免无依据的历史断言；本次锁定报告中的清单/姓名缺失路径，没有扩成统一表达系统。
- T2 关系失败未在本切片诊断；更广泛事实建议与自然配文/字数改写仍属后两项，未以本切片通过掩盖它们。
- 原诊断、首次失败、旧错误台词和隔离数据保留；临时观察代码清理，测试服务已停止。没有操作用户界面或正式身份。
