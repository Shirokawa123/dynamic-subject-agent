## 回归与修正过程

所有行为回归通过既有 ApplicationFacade；仅在 Provider/Transport 边界使用 stub，未模拟 Domain 写库结果。首次诊断重放仍保留在前一报告；原重放脚本修后退出码 0，5 个原错误症状均消失。知识正向答案采用原文上下文，不声称保留原来的任意自由改写。

3. 对抗审查发现完整句仍可能去掉跨句限定，随后合并还会删“目前没有证据”；改为完整条目上下文，并对证据采用完整合并。真实组合回归保留全部原文。
4. 审查发现纯词形会把过去叙述、作者询问、解释引用当成创作，或被同轮创作分句豁免活动/事实保护；修为命令分句检查，独立活动问题保持边界，只有本地核准并标明的 creative 表达才保留为创作。
5. malformed optional reply（list text/list kind）曾逃出检查，导致 pending；修后合法 Memory 正常提交、安全 base 保留。
6. 初版组合的裁决后重建吞掉已有姿态表达；改为合并 Memory/Knowledge 时处理两类表达，继续原有状态/目标优先级，并用实际组合状态查询回归验证。

## 限制与后续候选

- 事实段更接近明确的来源引用，牺牲部分自由改写自然度；创作标记也更显式。这是事实边界修复，不是整体角色表达体验完成。
- 明确创作/当前活动语法有界；未证明所有变体、隐喻、语言和对抗输入均能识别。模型可能再次误标 reply_kind，不能把一次真实复验当成长期零失败。
- 第 6 轮自然偏好未保存、第 8 轮关系子能力失败如实保留。关系请求和 Memory proposal 未修改；不将本次概括为六能力真实全通过。
