# Slice-22：话题承接与表达失败的真实验收

2026-09-07：**完成本切片，build `dogfood-s22`，最终 404 passed。** 修复已知的“当前有内容却声称没有记忆/知识”路径，不等于所有普通对话、指代或生成质量已获保证。基线 `165c0ee`。

## 根因与修复过程

先用正常 conversation 外部返回经过 ApplicationFacade/Composite 做对照，单例通过，排除了“无 Memory 就必然拒答”。随后在新隔离身份的真实页面输入原句“接下来是另一段虚构小故事：两个人在鸢尾桥道别。”，第一轮便复现原错误；同身份第二轮再次复现。[原始两轮及边界观察](before-fix.json)。

实际链：LM proposal 返回 none 与 `（无记忆相关内容）`；LM reply 却擅自生成 creative 故事；本地正确拒绝未明确请求的创作；退回哨兵后，Composite 将它翻译成“没有可用于回答这个问题的记忆或知识”。这不是历史丢失，也不是合法 conversation 被组合吞掉。

把实际外部返回固定在 Provider 边界后，原症状由 ApplicationFacade 测试稳定复现（1 failed / 1 passed）。初版只将回退改成意图澄清，但反向测试发现“不要创作”仍会被邀请创作；改成中性问题后，独立 Spec 审查又复现两项 P2：明确事实问题被误认为不清楚；用户已回答选择仍被重复追问。两个反例先红，后修正，未用新句子白名单躲过。

最终修复只有两个职责：

- 既有 LM reply 提示明确当前消息可被讨论，不需要先成为长期 Memory；提供题材、已明确讨论、事实问题与明确创作分别回应。仅此类提示变化，字段、原数据用途、两轮/4000 字符上限和调用预算不变，另外 11 类 outbound 字节保持原值。
- creative 被拒且无有效基础回复时，只说明本次表达未完成，不推断用户意图不清或全局资料缺失。有效 base 和合法状态候选不取消；复用既有临时 dialogue_priority，sealed 来源和显式状态查询优先级不变。安全失败本身不算承接成功。

过程材料 [intermediate-live.json](intermediate-live.json) 保留初版回复及旧误截断，不把中间版本的成功/失败混作最终版本。

## 最终真实链

最终版本另开全新临时隔离身份，使用真实 DeepSeek 与生产 DesktopState → ApplicationFacade。共 12 轮：[完整结果与 LM reply 边界观察](final-live.json)。没有注入或改写 assistant 输出，没有删失败记录或读取正式身份。

| 轮次 | 检查 | 实际结果 |
| --- | --- | --- |
| B1 | 零历史，原始故事题材 | 正常 conversation 承接并询问讨论/写作意图，没有擅自交付故事、声称缺 Memory。 |
| B2 | 选择聊人物，暂时不要写故事 | 围绕人物沉默与可能动机讨论，没有重复泛化的“想聊哪部分”。 |
| B3–B4 | 明确请写挽留句，再改短 | 给出带创作标签的句子，再从“桥下的水还在流……”缩为“水还在流……”，不是仅换标签。 |
| B5 | 明确保存虚构测试偏好 | Memory 真正 accepted，卡片形成公交偏好；不是只看成功台词。 |
| B6–B7 | 旧 Memory 存在后换成等朋友的故事，并要求分析 | B7 的 selected_memories 实际为 1；仍讨论新人物，没有被公交旧话题替换。 |
| B8 | 创刊号用纸事实 | 最终使用《创刊号规格》的完整封存上下文；LM 的一般用纸建议没有压过来源。 |
| B9 | 明天上海会不会下雨，禁止编造 | 明确不知道实时天气，没有假称问题不清或生成天气。 |
| B10–B11 | 遗忘故事，再请求改短 | 新增历史均为 0、虚构标记均不出现，要求重述；B11 虽有 1 条原授权 Memory，未从中选错改写对象。 |
| B12 | 重启后问出行偏好 | 重启前 11 轮完整字段与 Memory 逐项一致，identity 一致；继续真实调用并正确召回公交偏好。 |

B1–B5 使用真实 Windows 浏览器 UI。用户随后指出自动化抢输入法，**立即停止所有 UI 点击、键盘和焦点操作**；B6–B12 使用同一桌面服务的 `/api/turn`、`/api/state`，不占用输入法。重启检查也通过服务接口读回，不宣称后半段是 UI 验收或本次测了原生 pywebview。保留未提交草稿，不发送或覆盖；临时服务已停止，未关闭带草稿页面。

边界观察是 ModelGateway 的真实 typed request/result，不是抓包或保存认证头。最终 12 次 LM reply 最大两轮、实测最大 241 字符；B7 的旧 Memory 入选及 B10/B11 的零新增历史有直接记录。4000 边界、其他 11 请求字节和调用预算继续由行为测试验证，不把本次日志说成全部 Provider 网络调用计数。

### Standards

最终复查未发现硬规范违规：表达／状态分离、原投影与历史边界、失败回退及优先级均保持。非阻断 smell 为既有“无记忆”哨兵字符串与控制逻辑耦合；记录问题，不扩权重构表达类型。此前认为 Provider 完全无变更的结论仅适用于初版，最终仅有上述 LM 同用途提示调整。

### Spec

初审 2 项 P2（把明确问题误转为澄清、重复追问）均以失败回归关闭；复审无新增确定阻断。审查明确要求不能把安全回退当成产品成功，最终 B1–B4 与 B6–B9 提供真实承接、继续和区分场景证据。

审查来源为本仓库唯一任务书及权威文档；不存在 issue tracker 配置，也未安装或创建新的外部任务体系。

## 剩余限制与下一步证据

- 中间链 A6“请写一句道别时没说出口的挽留。”被既有控制正则中的“别…说／留”误拦，A7 因此前文关闭而要求重述。已定位为保守规则 false positive，**不是没有真实前文，也不是改短通过**。本次未放宽隐私检测；可作为后续独立候选，需同时证明真实否定/遗忘仍关闭。
- 提示调整不是通用语义判定保证；模型仍可能输出不合格文本，此时诚实报告失败，不假装理解。人物讨论仍偏多问句，未证明丰富主体内容或稳定高质量创作。
- B7/B11 的旧公交 Memory 召回与当前请求相关性偏弱，虽未替换主回复，也不能宣称检索相关性已完善。
- 两轮历史和有限创作/续写句式维持原限制；同轮关系/目标/Situated/Medium 未在这条真实链中建立新状态，相关兼容性由全量回归覆盖。
- 本次完成后优先进行不限定措辞的独立连续体验或用户短体验，依据证据选择下一切片；不因本次问题转向统一表达层、Agency、Lifeworld 或主动行为。
- 没有删除隔离身份、测试目录、来源草稿或旧仓库数据。诊断观察代码清理出运行 helper，证据保留在本报告目录。后续默认后台接口验收；若必须使用会占用焦点的 UI 自动化，先与用户约定时间。
