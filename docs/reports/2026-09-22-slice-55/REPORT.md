# Slice-55：有界角色对话的离线准备

2026-09-22，基线b1d9ba9。本片已完成可运行入口与离线检查；真实Provider调用0，真实credential读取0，人物生成质量未验收。

用户要从手写台词推进到真实人物聊天。已证实缺口是没有将起点人物依据独立用于自然回复的入口，旧多能力回复不应直接扩充小说资料。本片交付固定人物摘要、每次1次调用的临时会话、默认离线页面，以及[完整待批准方案](../../plans/character-dialogue-live-trial.md)。不要求用户体验固定回声；它只用于检查操作与数据范围。

## 实现与边界

- 新能力通过唯一ApplicationFacade进入CharacterDialogueSession，再调用ModelGateway的新character-dialogue-reply任务。旧12类模板未改。
- 新建独立空白承载身份以复用既有composition/生命周期，但不发送其Avery资料，不读取正式身份，不将实验文本写入任何canonical聊天记录。会话上下文只存内存，关闭丢弃；隔离目录下空白身份文件保留，不自动删除或迁移。
- 幂等绑定lab/revision/key/message/history；冲突、旧revision和超限不调用。20次尝试硬上限包含失败，进程真实入口只允许开一个实验；CLI真实验收仅六条、失败立即停，另外14次不是本轮授权请求。
- 最近两轮成功完整原话≤4000字符，撤回/关闭清空，重新开启不找回旧轮；保守控制识别可能误关。输出格式/字段/长度由Python检查，不能据此声称人物没有幻觉。
- 凭据只在明确发送时惰性读取；默认离线或错误digest不读取。后端不可用/缺key为unavailable，模型/传输失败为failed-closed；全部无自动重试。正文不会进入服务器访问日志。

## 复用与取舍

核对既有架构研究，并重新读取[Generative Agents原论文](https://arxiv.org/html/2304.03442v2)的架构与局限：它把经历和对话生成联系起来，同时报告记忆补造和过于正式的表达。这里借鉴按已知上下文生成/单独评价内容的分责，不搬入Reflection、自动生活或完整记忆流；相关性不能证明角色知情。本片未复制其代码、未增加依赖，因此没有新许可证/SDK集成成本。

优先复用本仓库的Facade、Gateway、DeepSeek单次Transport/严格JSON-envelope及保守对话控制；无第二持久化框架。S54本地来源依据只人工浓缩为固定小摘要，排除直播时间待核项、未来剧情和R1虚构日常；没有全书语义提取。成熟设计没有替我们解决原作还原，本片不以引用论文代替用户体验。
