## 实际结果

| 轮次 | 输入/行为 | 结果 |
| --- | --- | --- |
| T1–T2 | 公交经历后要求“按这个意思再写一句” | **首次失败**：T2 只给旧句加创作标签；尽管实际带有一轮 54 字符历史，仍不是新版本。 |
| T3 | 修复后原句复验 | “走错的路，往往藏着最对的心情。”；两轮 122 字符。 |
| T4 | 重启后“把上一句改短一些” | “往往”变“常”，有变化但改短很弱，不作为高质量润色证据。 |
| T5–T6 | 换成鸢尾桥虚构故事，再要求改短 | **第二次失败**：先回没有记忆/知识，后又改更早公交文案；当时新增历史确实包含新故事。 |
| T7–T8 | 遗忘故事，再要求改短 | 两轮请求的新增历史均为零、标记均不出现；后者要求重述。 |
| T9–T11 | 最终修复后重新建立旧话题，重放相同换题及改短输入 | 换题仍回没有记忆/知识；但改短只给最新一轮 46 字符，实际回复明确请用户贴出原句，没有跳回公交。 |
| T12–T13 | 明确“请写一句虚构小故事”，再改短 | 从“鸢尾花在风里低垂，他们松开手，像两片花瓣各自飘向不同的溪流。”改为“鸢尾低垂，他们松手，如两片花瓣飘向各自的溪流。”；保留创作标签，最新一轮 75 字符。 |
| T14–T15 | 最终代码再次遗忘，再改短 | 新增历史均为零、无标记；回复要求重述。 |

15 次实际 LM reply 均为 HTTP 200；新增历史最多两轮，本次实测字符最大值 129，字段恰为两项。T6/T11/T12/T13 标记确实曾出现在获授权历史投影中；T7/T8/T14/T15 均不出现。没有把“测试用标记从未进入历史”冒充遗忘成功。观察器只计 LM reply，其他 11 类请求的字节不变及调用预算由自动化/代码审查验证，不声称本次日志计数了所有 Provider 请求。

## 两处修复与验证

1. 明确续写不能完全复用上一条 assistant 正文；比较时只剥离受控创作前缀和首尾空白。失败只回退表达，区分“没有安全前文”和“没有形成新版本”，保留独立合法状态候选。Spec 审查再发现整条带前缀复制可绕过初版检查；补充第三种回归并修正重复前缀比较。
2. 整条明确“上一句/刚才那句改短”只从已经安全筛选的窗口取最新完整轮，不给更早话题作为候选；只缩小现有用途，不增加字段、调用或状态。LM reply 提示明确无可改内容时请求澄清。两个 ApplicationFacade 回归先红后绿，旧的普通两轮用例保留。

最终命令：设置 `PYTHONPATH=src`，以 `.venv/bin/python.exe -m pytest -q -p no:cacheprovider --basetemp=<全新唯一临时路径>` 执行。

**395 passed in 217.02s**。此前 393 passed 是第二次修复前结果，不能替代最终回归。新增目标测试首次调用曾因 PATH Python 无项目导入路径、默认 pytest 临时目录权限而失败；指定项目环境与全新临时路径后获得预期红测试。LM reply 提示哈希按授权更新，其他 11 项原哈希不变。

## 独立对抗审查

- **Standards**：最终增量未见新 store、扩大数据、额外调用或状态依据越界；缩窗位于安全检查之后，整轮保留。提示哈希和文档更新提醒已落实。
- **Spec**：重复前缀复制漏洞已关闭；最终缩窗增量无确定代码层阻断。要求真实验证拒绝/澄清路径，已由 T10–T11 覆盖。建议进一步覆盖旧话题仍被选为 active Memory 时的对象优先级；本次真实会话没有 Memory，不能宣称覆盖该场景。

## 留下的问题与范围

- 仅有限句式缩窗，混合消息、其他指代及 active Memory 与改写对象竞争不具备通用正确性保证；完全不同于自动长对话理解。重复检测不是语义质量评分，微小改写仍可能不好。
