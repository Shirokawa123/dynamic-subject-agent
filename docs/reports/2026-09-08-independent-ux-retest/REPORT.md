# 独立连续体验复验报告

## 总体判断

**未完成，且不能据此证明 dogfood-s25 的正常连续聊天体验。** 我以原创合成来源创建了新的临时隔离身份，来源预览、草稿保存、显式冻结和重启后的身份选择均有可观察证据；但第一条自然聊天消息在后台产品接口返回 `unavailable / intent-unavailable`，未进入 operation、未产生角色回复、说明或引用。因此约定的两段 20–30 轮连续对话及“重启前后对话恢复”均无法进行。

这是代理体验者的主观结论；可核验事实在 `raw/` 和 `TRANSCRIPT.md`。它不等同于视觉/UI 验收，也不等同于对桌面交互路径失败的证明。

- 未修改产品代码、Provider 配置、凭据或正式身份；未读取旧救援仓库、正式身份数据、私人来源、实现代码、测试、历史体验报告或修复验收脚本。
- 已知背景仅包括仓库规则所要求的 `AGENTS.md`、`docs/PRODUCT.md`、架构的外部 seam/数据边界、`current.md`，以及 README/STATUS 中的启动和当前状态说明。README 虽链接历史报告，但该报告没有被打开。这个背景使本次不是完全盲测。
- 仅以后台 `ApplicationFacade` 路径进行；未操作输入法、窗口焦点或未提交草稿，未声称完成视觉/UI 验收。

## 方法与实际流程

我选择的普通目的本是：和“林柚”聊一张空白明信片，再共同把它写成一条短句并修改。先对原创合成来源完成提取、保存和 freeze；首次 mapping 使用了不在来源身份证据内的显示名而被拒绝，随后按一次普通澄清改为来源中的“林柚”，成功创建并选择新身份。

进程在保存后关闭，并在下一次进程中完成 mapping/freeze/select；`raw/05-restart-evidence.json` 是该重启后选择的后台返回。之后第一条自然消息的最终接口返回是 `unavailable / intent-unavailable`，无 `operation_ref`，故没有可等待的异步结果。为避免把体验变成猜测内部命令参数的测试，我在这一明确阻断处收口。

## 主要问题

### P1：后台路径无法开始自然对话（可复现范围未知）

- 用户当时想完成什么：就一张空白明信片共同想一句送朋友的小句子。
- 实际发生什么：提交返回 `status: unavailable`、`problem.code: intent-unavailable`；没有 operation、主回复、说明或引用。见 `raw/04-chat-submission.json` 与 `TRANSCRIPT.md`。
- 分类：**无法确定**。它可能是后台接口调用路径/临时身份可用性问题，也可能是桌面 Adapter 才会填充的 intent 契约；本次未使用视觉 UI，不能归因成桌面用户必然会遇到的功能失败。
- 后果及恢复成本：用户无法开始聊天，无法自行从该返回恢复；体验者若继续，只能猜测内部参数或转向 UI，这两者都会破坏本轮约束与独立性。成本为阻断。
- 是否复现：只观察到一次真正的自然消息提交。其前的三次 `PreAdmissionRejected` 发生在构造后台命令的规范阶段，均未到达产品 operation，未计为用户对话失败；详见 transcript。

### P2：来源冻结的显示名拒绝缺少普通用户级引导（单次观察）

- 用户当时想完成什么：将已保存的原创来源候选封存为临时隔离身份。
- 实际发生什么：显示名“林柚（复验隔离身份）”被拒绝，`problem_code` 为 `source-freeze-display-name-not-in-identity-evidence`；将显示名改为来源证据中的“林柚”后 mapping 和 freeze 成功。
- 分类：功能限制的表达质量问题，而非安全越权。
- 后果及恢复成本：知道原因代码的技术体验者可一次澄清恢复；普通用户若只看到抽象代码，未必知道需要直接采用来源身份名。本次恢复成本低。
- 是否复现：一次失败、一次同源名字成功；未扩大到其他来源或 UI。

## 隔离与安全观察

没有发现正式身份、旧救援数据、私人来源或密钥被写入本报告的原始返回。来源候选和 freeze 映射均只引用本次原创合成文本。由于聊天未进入运行周期，不能对记忆隔离、关系声称、无依据活动、遗忘、更正、创作修改、失败后续谈或重启后的对话历史做正面或负面结论。

## 最多三个后续重点

1. 先复现并界定 `intent-unavailable`：在与本次相同的新来源隔离身份上，确认桌面 HTTP/UI Adapter 与后台 product seam 对第一条普通消息的 intent 是否一致。证据是本次无 operation 的首次提交；影响是连续体验完全无法开始。
2. 审视来源 freeze 的错误呈现：把“显示名必须来自 identity evidence”的可操作说明提供给用户。证据是一次可恢复的 mapping 拒绝；影响低，但会在首次建角时造成停顿。
3. 在问题 1 排除后重新做独立连续复验：本次没有足够事实去评价记忆、更正/遗忘、创作修改、身份边界或重启后的 20 轮历史，不能用既有成功声明替代。

## 限制

本报告只覆盖后台接口，不覆盖视觉界面；一次 `intent-unavailable` 不足以判定 UI 功能失败。没有执行 20–30 轮，也没有做聊天后的重启恢复，因为没有一条对话可提交。临时运行数据留在用户临时目录，未作为报告交付物复制；报告所需的脱敏接口原始响应已保存于本目录。
