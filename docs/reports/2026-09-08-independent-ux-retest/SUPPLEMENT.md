# 补充复验：桌面 Adapter 路径与连续体验

## 结论更新

原报告的 `intent-unavailable` 已证实是**接口调用问题**，不是自然语言被拒绝，也不是已证实的产品聊天失败。保留原始失败及其原始响应，不改写历史结论；本补充通过实际桌面后台 Adapter 的 `POST /api/turn`（仅 JSON `{text}`）重新提交了完全相同的首条明信片消息，得到 HTTP 200、`ok: true` 和已提交的第 1 轮。

此后在同一临时隔离根、同一“林柚”身份完成了 20 个已提交轮次：重启前 12 轮，真实停止服务并重启后 8 轮。重启后服务读到 12 条 canonical history，并在第 13、16、18、20 轮使用已提交的计划/记忆。这个结论仍只适用于后台 HTTP Adapter，**不声称已做视觉/UI 验收**。

## 分类

### 已证实的接口调用问题

1. 原 `intent-unavailable` 来自错误的后台调用契约（`conversation`），并非首条自然语言本身。相同文字经 `/api/turn` 成功提交，见 `raw/06-adapter-first-turn.json`。
2. 原报告把“显示名不在证据中”的后台 code 延伸为“UI 缺少引导”没有证据支撑。经本轮核对，桌面界面对该情形有中文提示；原报告现在只保留它作为**后台 mapping 限制**的单次观察，不再对 UI 引导作结论。

### 已证实的产品体验问题

1. 创作的首次请求未完成：第 2 轮要求“给我一版不煽情、像傍晚窗边的明信片短句”，系统只引用来源并说不能确定；第 3 轮的“改短”才给出一条标注为即兴创作的短句。后续重启后的第 14、15 轮两次创作/修改请求均返回“没能给出符合你请求的回复”，没有用擅自创作冒充完成。影响是用户的共同写作主线断续，恢复成本是改为自己写或下次重试；本轮没有继续换句式凑成功。
2. 第 8 轮含糊遗忘被清楚拒绝，第 11 轮在用户按提示提供完整原文后成功逻辑遗忘。这个失败是安全限制且可恢复，不是产品功能失败。

### 仍无法确定

- 不可据 20 轮判定视觉界面、所有语言/创作风格、所有身份隔离路径或任意复杂关系场景。
- 第 19 轮对被遗忘偏好的追问没有把旧偏好重述为活跃记忆，且没有显示泄露；但它以封存“合作偏好”作答，不能单凭此轮证明所有遗忘后的 Provider 投影都正确。
- 第 6、7 轮的同一句“更正”重复，是命令批量超时后第五条已先提交、体验者误以为未提交又发了一次；保留为事实，不将两条重复当作独立功能复现。

## 连续体验观察

- 来源外的“今天谁来借书”和“是否今天去上班”均回答为资料不足，带有对应封存来源引用，未声称当天活动。
- 对“我和邻居已经有什么关系”回答没有直接把关系当作确定状态，并有“单方面关系声称不会直接改变关系”的说明。
- 第 5 轮偏好形成记忆；第 8 轮拒绝后有明确可恢复提示；第 11 轮确认旧原文保留、不是物理删除。第 12 轮计划被记录，重启后第 13、16、18、20 轮可见其被召回。
- 报告中的完整按序用户文本、主回复、说明与引用见 `TRANSCRIPT-SUPPLEMENT.md`；脱敏 HTTP 证据见 `raw/06` 至 `raw/08`。

## 后续重点（不设计架构）

1. 复现第 2、14、15 轮的创作未完成：证据是自然的首创作请求及重启后两次连续失败；影响是“共同写短文”的核心目的需要用户放弃或另寻写法。
2. 将后台接口使用边界记录在复验/运维入口：证据是原先 `conversation` 与 Adapter 的 `ask-collaborator-status` 差异；影响是非 UI 的合法后台验收会误判产品不可用。
3. 在独立后续复验中扩展遗忘后的最小投影检查：证据有限，不应把第 19 轮单次不重述当作完整隐私证明。
