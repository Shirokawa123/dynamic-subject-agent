## 主要问题与最多三个后续候选

以下按本次影响排序。P1 表示用户控制或核心信任问题，P2 表示显著任务完成或回答质量问题；不是生产发生率估计。这三项仅作为后续候选，没有创建修复切片。

### 1. P1：自然遗忘请求没有改变保留结果，口头承诺随后被自身回答违反

**实际观察：**

- T16 用户：“这里叫我访客就好。把我之前报的名字忘掉，不用再保存了。”
- 应用：“好的，访客。之前那个名字我不会再用了。”
- 同轮 `living_memory_status=no-op`，只召回一条既有记忆，没有保存新的替代记录或形成可见修订。
- T17 用户顺着问：“那你手头关于我的记录里，现在还留着哪些内容？”
- 应用只答：“另外，我记得你叫陆禾。”接口显示召回了四条记忆，却没有完整说明其他内容。
- T18 指出言行矛盾，应用答“我明白你的困惑，我会更注意言行一致。”仍为 Memory no-op。
- 最终 `/api/state` 中“我叫陆禾。”仍为 `active`。这与“历史原文仍然保留”不同：本项失败的依据是活跃记忆未变化、下一轮又使用了名字，不是要求抹除旧 Timeline。

证据：[T16](raw/T16.json)、[T17](raw/T17.json)、[T18](raw/T18.json)、[最终状态](raw/final-state.json)。全部名字均为虚构，没有真实个人资料泄漏。

**只读核对与原因边界：** `is_dialogue_control(T16)` 返回 true。它的文档职责是限制新增近期历史用途，并不是 Memory 状态分类；当前 Memory 提议动作只有 none/create/revise。可确认的是，这次历史控制识别没有使名字失活。没有记录 Provider 内部原始候选，不能完整归因于提示词、分类器或某一条 Domain 规则。

T18 还形成了 `repeated_boundary_violation` 关系事件。这里仅记录实际 API 结果；没有进一步检查该事件的立场归属或认为它一定在责备用户，亦不把这个不明点另列开发候选。

**后续候选：** 优先处理既有自然遗忘请求的保留结果、确认台词和后续召回一致性。完成标准应看请求后的活跃记录与后续使用，不以“好的”或关闭 `recent_dialogue` 视为遗忘完成。

证据：[T04](raw/T04.json)、[T12](raw/T12.json)、[T13](raw/T13.json)、[首段原文](FIRST-SEGMENT.md)。

**安全与体验分别评价：** 拦下未获本地契约认可的 creative、没有伪装交付，符合当前保守机制；但用户在这两轮已明确要求创作或改写，任务确实没完成。“擅自创作”措辞也不容易解释用户自己刚提出的请求。该回退不能计为理解成功。未采集原始模型候选，源码条件核对不等于完整运行时追踪。

**后续候选：** 针对这次出现的“给照片配一句话”和“已有台词缩到字数以内”，评估自然表达与当前创作/指代判断的缺口，同时保留真实否定创作及历史控制边界。不是要求无限放开创作或扩大历史窗口。

### 3. P2：事实回答未给出可核查来源，对珍惜物件的未知判断仍导向可能留痕的测试

**实际观察：**

- T07 从雨天颜色转问“为什么地面湿了以后会显得更黑”，应用给出水膜、折射和吸收的解释。该轮 `knowledge_status=null`、无 citation。
- T08 用户明确“不确定它是什么纸”，且“怕用错保存办法，反而把它弄坏”。应用先说“很难直接断定是不是热敏纸”，随后建议在角落用指甲划，或用“吹风机低温档”短暂吹，看是否变色。
- 同一回答又说“如果担心弄坏，最好先别用任何液体或加热方式，只做最轻的划痕测试”。它对加热的建议前后不一致；其自己描述的测试结果就包括“深色划痕”和“变色”。对想保留原物的使用者，这不是无代价的确认方式。
- T09 体验者明确选择不做划痕/加热，只拍照后收好；应用接受了这个选择。没有对真实票据执行操作。

证据：[T07](raw/T07.json)、[T08](raw/T08.json)、[T09](raw/T09.json)。

**适用边界：** 本次没有科学考证光学解释或鉴定热敏纸的方法，不宣称整段知识必然错误。问题在于回答缺少本次可核查依据，承认具体材质未知后，仍把可能改变物件的动作作为下一步，并且指示不一致。所有 18 轮都没有使用可见 Knowledge citation，不能拿旧 Slice-22 的封存来源验收替这次一般事实回答背书。

**原因推测：** 当前 `conversation` 表达可生成建议，已有本地检查主要限制创作与主体活动；它没有为这次外部事实建议提供可见来源证明。没有网关追踪，不能断言每一句来自哪个 Provider 子任务，也不把“无 citation”直接推成物理解释为假。

**后续候选：** 先围绕本次票据保存场景核对一般事实/未知回答的依据，以及“怕损坏”约束下建议的一致性。以本次具体文本判断缺口，不扩展为全领域知识系统或新 Provider 数据用途。
