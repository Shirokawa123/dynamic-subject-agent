# Slice-30 记忆回答契约（实现前方案）

基线 fb28c36。ApplicationFacade 原样复现 head89/head94 两类症状：2 failed in 3.41s。测试检查了 reply 实际收到完整周日记录或空 tuple，错误仍原样显示，因此这些对照中的候选遗漏、输入丢失已排除。原真实 head89 只保留脱敏 ID，不能倒推当时具体选中对象。

## 比较与选择

1. 增补「尚未安排/不清楚」等输出词表：只能覆盖改述中的部分台词，不采用。
2. 仅追加提示要求准确：自由文本仍可否定自己收到的记录，无法使 Python 约束回答依据，不单独采用。
3. 在既有 capability-local reply 中分离记忆回答类型，由 Python 使用本轮选中记录形成正文：采用。没有新模型阶段、统一表达、历史用途或状态写权。

## 精确契约

- Memory reply 请求四项 current_user_message、selected_memories（最多5条content）、runtime_identity、recent_dialogue（最多两轮/4000字符）不变；其他11类请求字节不变。
- 响应字段仍恰为 reply_kind、reply_text、language。reply_kind 新增 `memory`，既有 conversation/creative/activity 保持。memory 表示当前在回答既有用户记忆/安排，不表示模型已证明存在相关事实；reply_text 可为空，其自由内容不显示、不成为证据。
- Python 仅从当前披露校验后的、实际上送入 reply 的已选记忆形成完整原文引用；非空时说明「你之前说过」，不追加日期推断、不删条件与否定句、不要求重复确认；多条只列出这些记录，不猜唯一对象。
- 选中为空时固定说明「这次没有可用于确认这件事的记录，暂时无法确定」，不说未发生/未安排/从未提供，也不说明已遗忘（这些状态仍须 canonical 专用路径证明）。披露失败/未决控制时使用已有可用范围无法核实说明。
- memory 类型的自由回复不经过回退重新复活；生成失败且没有有效类型时仍遵守原有 failure/fallback 契约，不宣称对任意误分类、模型失败或自由表达实现完整语义核验。模型将记忆问题错标为 conversation 的风险必须在真实改述中检查、如实报告。
- `memory` 不是全局事实豁免：当前活动、提醒、无来源外部事实、精确状态、创作/续写/编号修改等既有边界仍优先；需要防止同轮其他能力附加自由回复覆盖记忆依据。

## 限制

候选错选不会因为原文引用而变成正确召回。本切片记录 proposal 实际选择内容、reply 实际输入和类型、最终正文分别是什么，不用数量冒充对象证据；未相关的引用仍是体验失败。此机制不证明任意自然语言的意图分类或所有复合问题都正确，也不把只说“周日”提升为唯一公历日期。
