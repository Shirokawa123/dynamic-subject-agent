# 完整角色系统：代码证据、补充检索与方案取舍

2026-09-24，Slice-76。研究基线 `f04c117`。本文区分仓库事实、来源发现与设计判断；没有运行新Provider实验，没有引入依赖或读取小说全文。

## 一、为什么需要重推，而不只扩写旧方案

用户要得到可长期相处的虚拟人物。此前全局文档已列出创作、相处、生活三闭环，但还未回答：什么变化必须持久化；开放语言怎样成为有限世界中的行动；何时形成信念而非世界真相；没有任意生活生成时如何保持丰富；怎样证明新增结构胜过简单角色卡。

本轮将这些作为研究问题，不把文档数量、心理标签和工程测试数作为产品证据。

## 三、本轮补充一手资料

### LongMemEval：不能把长期记忆压成孤立事实

来源：[原论文§3–5](https://arxiv.org/html/2410.10813v1)、[作者代码](https://github.com/xiaowu0162/LongMemEval)。论文分信息提取、跨会话推理、时间推理、信息更新和无法回答时保留；实验比较索引、检索、读取，单轮粒度与检索键扩展各有作用，过度压成事实会丢信息。

本项目推论：共同聊天保留带说话者的完整轮/事件为可回溯依据；摘要和检索关键词只当可重建索引。角色曾经说错的原话不能升格为世界事实。分别测召回正确依据和最终答复，才能区分材料未取到与取到仍编造。该QA基准不测角色生活、自主意见和长期亲密关系，不能拿其分数代替本产品体验；本轮不复制数据或运行其评测。

### Lost in the Middle：全量输入也须接受基线比较

来源：[TACL原论文](https://aclanthology.org/2024.tacl-1.9/)。论文在多文档问答与键值检索中发现相关信息的位置会影响效果。

本项目推论：不能以“上下文放得下”证明“信息会被正确使用”；实验应交换材料顺序并比较全量、压缩核心、核心加检索。研究使用的模型和任务与本项目不同，不能预断2026年的某个API模型必然同样失效，也不能据论文强行安装检索框架。小资料包全量输入可能胜过低质量检索，应保留其为有效基线。

### BookNLP：资料预处理的成熟分工与适用限制

来源：[官方README](https://github.com/booknlp/booknlp)、[MIT许可](https://github.com/booknlp/booknlp/blob/main/LICENSE)。项目面向英文书籍，包含人物指称聚合、共指、引语说话者及事件标注。

本项目推论：小说人物处理必须先解决“谁对谁说、指的是谁、在何种叙述情境”，再组织人物认识；不能仅搜索人物名字附近句子。现有材料是中文译文，不能假定英文模型可直接用。此次未导入代码；提交历史页抓取失败，维护活跃度未确认，不称其可直接生产集成。引用此项目作为流程分工依据；具体中文工具需后续带实际样本评估、模型权利与许可证核验。

### SQLite FTS5：中文检索不能直接套默认配置

依AGENTS读取并使用context7-mcp技能，调用`resolve_library_id`查询SQLite tokenizer行为，返回`TypeError: fetch failed`；按技能转查[SQLite官方FTS5文档§4.3](https://www.sqlite.org/fts5.html)。默认unicode61按连续token字符分词；trigram按三个字符切分，全文查询少于三个字符的子串不命中。

本项目推论：不能说“加FTS5就实现中文语义检索”。两字人名、别名和同义转述须在基准中出现。小规模先用审核过的场景/别名关联和可解释检索基线；再比较中文切词、字符索引或本地语义向量。FTS/向量均为可重建投影，不建立第二事实库；本轮没有安装库、下载模型或外发embedding。

## 五、未采用路线及反证条件

| 路线 | 能解决什么 | 当前判断；怎样推翻判断 |
| --- | --- | --- |
| 单份角色卡＋全量历史 | 快速自然聊天，构造简单 | 必须保留为成本/质量基线；不能独自裁决新生活事实和权限。若在同预算冻结场景中不输复杂检索，则保持简单上下文 |
| 角色卡＋通用RAG | 扩大资料覆盖 | 可用于只读资料；不足以维护原作时间、角色知情和后续事件。若加入最小元数据过滤已足够，则不自建图查询系统 |
| 全社会多Agent模拟 | 他人行为与涌现故事 | 计算成本、额外事实源及长期可控性不适配首版；若单人有限世界在连续体验中确因他人无主动性而失败，再限定新增旁人物 |
| 微调专属角色模型 | 可能改善稳定语气和部分知识 | 先无法解决分支事实/事件真值，数据和训练成本新引入；只有资料与运行链已正确、风格仍稳定失败才评估 |
| 硬编码全部剧情与回复 | 重现性强 | 可作测试替身及严格剧情骨架；难以满足新情境和自然相处。自由分支需要有限动作规则＋开放表达 |
| 规则维护权威、模型提出语义内容 | 可恢复事实、自然交流和受限开放生活并存 | 推荐；主要风险是语义错误仍漏检和活动贫乏。若相比基线只增加字段/延迟而不减少失败，应撤掉该层复杂度 |

## 六、尚未证明的事

没有论文证明这套组合可在目标人物和现有Provider上持续自然运行。尤其是自动全书建角、长期情绪/关系更新、自由台词不添事实、有限活动是否有趣，均需产品实验。按主方案分阶段收集这些证据；批准研究不等于批准原文/历史外发、后台通知或人格自动改写。
