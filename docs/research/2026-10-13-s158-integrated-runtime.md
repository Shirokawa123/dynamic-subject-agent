# S158开工证据：一个权威状态中的交流、活动与分享

结果与验收沿[S158](../slices/slice-158-integrated-character-loop.md)。已证缺口是feedback与living互斥的资格、schema和裁决分派，不是缺少另一个Agent框架。只读调查核了两种实际builder与S142/S150批准，不将相同字段形状视为新来源跨用途已获准。

## 定向一手核对与取舍

- [Microsoft Event Sourcing](https://learn.microsoft.com/en-us/azure/architecture/patterns/event-sourcing)：事件流是权威，视图可从中重建；并发写需以已读版本核对，历史事件不就地覆盖。仓库已经实现这些机制，因此复用Timeline/Publication，在同一记录中协调已有living和feedback字段，不引入消息总线、第二store、云或新的事件框架。只借架构机制，不照搬其自动重试建议。
- [RFC6902 §4–5](https://www.rfc-editor.org/rfc/rfc6902.html)：条件检查与替换、失败不当整体成功。沿S150/S154已适配的版本核验与完整精确frame，仍由Python构造/终审；没有采用整份计划自由重写。JSON Patch本身不规定本仓的字符跨度算法。
- [S150人物交流研究](2026-10-11-s150-natural-feedback.md)的局部澄清适用于本轮；本次只整合已有机制，无新心理状态或人格推断，因此不扩建心理模型。交流自然度仍待真实完整场景验证，不由架构模式证明。

上述官方资料于2026-10-13定向搜索并读取；这次不依赖新库/SDK/云API行为。无外部代码、依赖或部署引入，无新增第三方许可或维护负担。保留现有Python标准库实现和已有许可；未采用外部Agent框架或新数据库，因为没有当前能力缺口需要它们。

## 实施决定（LOCAL准备，非新用途批准）

1. 独立组合资格/schema9，旧schema6/8与旧资格保持；同SharedActivityRecord、同canonical、同Facade。一个组合Cognition协调普通消息/活动/分享，最终Publication只调用一次组合裁决器。
2. 普通消息使用唯一raw `{intent,reply_text}`协议，剔除旧输出说明冲突；其他本地六字段/多跨度edit由Python绑定，原4096及完整保护不变。直接输出只作为已诊断支持的技术选择，未宣称人物效果已过。
3. S1仅供分享后两次普通接话；当前方案的精确编辑结果独立由原plan与本轮完整F计算。先核frame，再将S1依赖加入回复；不将临时S1窗口并入持久plan依赖。依S1才能定位的自然指称必须澄清，不能伪称独立编辑。E/F撤回仍传递过滤方案、分享和回复。
4. 共享生活开关、在线机会、分享上限、幂等和恢复。普通聊天失败不产生事件，生活动作失败需关注；未知交付或权限故障沿现有关闭逻辑。所有真实外发仍需准确grant，不因LOCAL可用自动启用。
5. 最小待审差异：feedback增加有效S1及其合法派生近期交流；在线choice增加现有F1；share允许F派生plan但不发F原话。先完成实际LOCAL链与准确投影样例，再集中申请这些用途及需要的新入口启动。旧批准用途不重复申请。

验证通过Facade同身份完整链、S1过窗后plan仍有效、来源/历史关闭过滤、原精确编辑保护、失败与重开/原nonce恢复、旧schema兼容。模拟生成只能证明工程流转；原真实失败和未提交成果保留，不运行旧场景。
