# 角色生活：从开放语言到可接续事件的机制复核

2026-09-24，Slice-76专题研究。本文补充[整体方案](../plans/global-product-architecture.md)中尚未落到运行机制的生活、时间与主动分享；不改变PRODUCT已确认方向，不授权模型外发、后台服务或通知。本轮只读公开一手资料与代码，未读取私人素材、未调用项目Provider、未引入依赖。以下数值均为待测实验配置，不是用户已同意的生活速度或费用。

## 1. 用户结果、已证实缺口与验收

用户隔天回来，人物可以讲起一件与自己在意的事有关、有具体变化、可能未完成或失败的事；继续追问时，人物能接续相同的项目和后果。用户未回复时，人物仍有可继续的日常，但不会用催促和突然发生的大事惩罚缺席。

当前代码的`character_dialogue.character_context()`将`established_life_events`固定为空，注释明确实验没有事件写者；`conversation_basis.py`也校验实验生活事件区为空。ARCHITECTURE的时间基线只把TemporalAnchor渲染为当天措辞，不产生新经历、状态转移或提醒。因此“往上下文多塞几条近况”会绕过缺失的生活权威，不是完成生活功能。

最小验收不是“角色说昨天画了画”，而是能沿同一分支查到：为何开始→何时尝试→允许的结果→具体留下什么→如何影响下一步→为何愿意向该用户分享。关闭、重启、重复唤醒后这条链仍一致；无预算或生成失败不能冒充角色经历了挫折。

## 3. 可运行的最小机制：有限规则托住开放内容

推荐“有规则的局部生活＋开放的主题和表达”，不是无限自然语言世界，也不是一串固定台词。世界模型只记录会改变后续行动或纠错的内容；初期只需项目、阶段、可用资源、具体产出/问题和少量情节门槛，先不建饥饿、体力、金钱等全套数值。

### 3.1 开放语言如何进入运行权威

1. **形成意图候选。** 模型读取人物核心、一个当前关注、当前项目和许可行动，提出`activity_kind + target_project + bounded_parameters + supporting_basis`。自由文本说明“为什么想做”不自动成为新生平；不要求输出或保存推理链。
2. **确定可执行含义。** Python对照活动契约：该人物是否有相关能力和工具、项目处于哪一阶段、所需对象是否存在、允许改哪些状态。模型没有权创建新动作类型。无法落到契约的想法保留为愿望或待支持候选，不谎称已执行；不必因此拒绝继续聊天。
3. **执行世界转移。** 本地规则决定是否能开始、占用多少逻辑时段及允许哪些结果。结果可由规则直接给出，或从预先定义且满足条件的结果集合选择；若有抽样，样本与规则版本在提交时固定，重启不重抽。抽样权重是创作设计，不是假装测得的真实成功概率。
4. **形成事件及可见结果。** 提交项目变化、产出版本、受阻原因、原因事件引用和逻辑时间。角色能够观察到什么单独确定，不能让她立即知道远处人物的隐秘动机。
5. **解释和表达。** 模型可在既定事实范围内解释重要性与生成台词；新状态提议仍需接纳。未经检查的自由描写不能在以后倒灌为世界事实。

这里最难的不是JSON，而是开放文本里的暗含事实。例如“终于画好了，哥哥夸了我”包含两件事：完成自己的作品与他人的反馈。第二件事需要独立互动事件，不能借第一件事的成功一起放行。首期可写产出内容的主题、构图意图等局部属性；不能顺带生成订单、获奖、他人承诺、外出或重大关系改变。Python能控制状态槽位与许可，不能保证任意散文完全无暗含事实；严格事实骨架、针对性语义复核与内容验收缺一不可。

### 3.2 事件生命周期与失败必须分开

`拟做 → 已接纳计划 → 已开始 → 进展/受阻 → 完成/主动搁置`是可观察区别，不必各建独立服务。一次尝试失败不等于目标永远失败；新信息可能开启替代路线。每次接纳包含原分支版本，聊天或其他生活推进已改变前置条件时重新裁决，不能提交过期成功。

另外保留运行层结果：`无适用活动`、`预算不足`、`Provider不可用`、`候选未通过`。它们不能被翻译成“她今天很失落”“画坏了”或“她不想理你”。只有虚构世界的真实受阻事件才能支撑人物挫折。

反事实可用于提出下一步：“如果试试更简单的背景会怎样？”其结果属于临时预测，没有事件ID，不能进入已发生经历、关系依据或分享库存。模拟候选、已接纳计划与真正结果需要分别读写；一个方案看起来会成功，不等于已经完成。

## 4. 一个有意义的有界活动例子

以下为新分支的设计例子，**不是原作事实或已发生的纱雾近况**。前置是角色定义已确认具有绘画能力；不额外假设商业委托、观众、设备型号或具体家庭互动。

**关注**：希望用少量线条表现一种动态感。**项目**：一张个人创作，保留稳定项目ID与当前方案；它是虚构作品对象，不宣称已生成可下载图像。

| 步骤 | 真正写入什么 | 后续可观察差异 |
| --- | --- | --- |
| 选择方向 | 主题、在意的表现目标、选择来源；用户曾建议只是依据之一 | 她可接受其中部分，也可说明自己选择了别的方向；不把用户建议变成强制任务 |
| 构思两种小方案 | 两个方案各自的局部取舍及选择；未选方案仍是方案 | 之后能解释为何选这一版，而不是只说“进行中40%” |
| 尝试第一版 | 一次已发生尝试、保留的版本及待解决问题 | 允许出现“方向成立但还不满意”的部分结果；不是非成功即彻底失败 |
| 调整或搁置 | 针对上一问题的具体修改，或暂缓理由 | 次日仍记得是同一张作品，修改前后能比较；暂缓不抹去旧稿 |
| 接纳为完成 | 当前目标已按活动规则满足、作品版本固定 | 可以分享这个结果；不能顺带断言别人喜欢或它达到客观艺术高分 |

如果世界不实际生成并分析图像，就不能让模拟器假装客观证明“透视准确、技巧提升20%”。可以成立的是角色做了两种方案、比较后选择其一、决定这一版达到本次意图；艺术满意与世界物理事实分开。后续若需要真正给用户看作品，应增加图像产出和版本对应的独立能力与数据用途。

有限域的丰富性来自几种可组合后果：跨日保留的项目、不同意图对同一操作的取舍、局部成功与返工、多个关注间的选择、过去作品影响下一次尝试。更换形容词、随机换心情、每天新开一个项目不算丰富。活动无新决策或结果时可以安静，不必自动每天造“有趣小事”。

首轮可以用绘画验证，但活动规则应按“创作项目”的阶段写，主题由人物与当前分支决定。第二个人物换成写短篇或做手工时，系统应复用时间、提议、提交、分享机制，只换动作/资源与结果契约；若每个角色都要重写整套运行器，则抽象无效。

## 5. 时间、离线补算与重大节点

### 5.1 两只钟，一种事件语义

现实钟用于唤醒、免打扰与频率限制；虚构逻辑钟用于活动先后和进度。现实过去多久只产生可推进额度，不能直接证明某活动成功。活动记录需能区分“何时补算写入”和“虚构世界中的时段”，避免把补算冒充曾实时运行。

采用同一个推进入口处理应用打开、后台唤醒与手动快进；它接收目标逻辑时刻、最大决策步数、最大模型预算及请求身份。推进到**下一个有意义的决策或结果边界**，不是每秒调用模型。确定性等待和例行持续可跳到下个边界；不可跳过产生新事实所需的裁决。

以实验配置举例：一次打开至多结算3个决策步，达到重大节点、预算耗尽或目标时刻即停。长期离线不积攒无限模型债，也不能为了赶上现实日期瞬间完成所有项目。剩余额度保留为明确滞后；如采用略过无事区间，只能记录“该区间未细化”，不能以后回答里面具体发生了什么。时间比例、离线积压上限以及是否运行后台，均待具体可评方案再确认。

### 5.2 重大节点必须是运行中的门槛

在身份暴露、重要关系变化、离开既定生活环境等重大结果之前，先产生“可参与的待决节点”，其条件包含受影响事实、允许的选项/意图范围与等待策略。不是先写入大事再发消息让用户追认。

默认等待时，推进器禁止结算这个结果及其依赖后果；可继续的仅是与其无因果冲突的日常。没有明确兼容证明时停在边界。等待不应产生自动过期惩罚、催促或关系扣分。用户参与可用普通文字表达，不必固定按钮；若意图不清且会导致不可逆结果，保留节点并澄清。完全自主配置可允许角色选择，但并不授予新增Provider或现实工具用途。

严格原剧情模式是另一种世界裁决：里程碑有原作先后与条件约束。开放聊天若提出会破坏下一里程碑的行动，必须有明确冲突语义；不能一面承诺严格剧情，一面让模型随时改写。第一生活实验应选已确认的默认分支模式，避免把严格模式伪装成一句提示词。

## 6. 主动分享：从事件到愿意说，再到送达

分享选择应读取已提交事件、该用户已知部分、当前关系/话题及分享意愿。第一版可用简单顺序：有新后果且与人物关注相关→愿意对该对象说→未分享/不过时→允许联系。事件的重要性不等于隐私可公开；严重事件也不当然适合立刻发给初识网友。

“每天最多两次”只是硬上限。没有值得分享的事便不调用表达模型；多个相关进展合并为一次近况，已经通过进行中的聊天讲过的内容不再作为新话题投递。未回复不引出重复提醒，不把未读时间自动变为被抛弃的情绪依据。

实现上仍使用现有唯一Timeline：生活事件、分享候选的接纳、生成后的待投递消息、渠道结果分别成立。同一事件可以不分享，也可以只分享其中一部分。消息生成失败保留事件与待处理意图，不回滚成“事情没发生”；投递失败不能变成关系经历。重试使用原消息ID，重启后不重新生成另一份近况。分享前若用户已在聊天中知道该事件，重新检查可取消旧候选，避免同一天重复告知。

本地收件箱先做可靠投影，用户回来可看见原消息；应用彻底退出时若未运行后台，不能声称通知仍有保障。外部通知发送后崩溃但回执缺失时维持送达unknown，恢复策略依渠道能力决定，不以盲目重发伪造exactly-once。

## 7. 预算与验收：先证明后果，不增加组件数量

### 预算样例

不在本轮估计货币价格。可先设单人物实验额度：每天最多6次活动决策生成＋2次分享表达，总上限8次；修复/重试同样占额度，不能悄悄加调用。若每次输入2,500、输出350 token，上界是20,000输入＋2,800输出token/实验日，再按实际授权模型价格换算。零变化的唤醒使用0次模型；暂停也是0次。与用户正常聊天的预算单列，不能被后台补算吃光。

这是测量起点，不是需要每天用满的配额。定时器不承担复杂推理；规则裁决、去重、频率与等待状态在本地执行。若把计划、世界裁判、情绪、记忆总结、分享意愿和台词全部拆成调用，单次事件会先天昂贵，应要求每次新增调用在盲评中证明收益。

### 可观察验收

| 场景 | 通过表现 | 能揭露的虚假完成 |
| --- | --- | --- |
| 连续3个虚构日，同一创作项目 | 方案、具体尝试、问题和后果可接续；追问不临时重写 | 每日只生成独立近况或进度百分比 |
| 减少资源或变更前置条件 | 原方案受阻，存在时改走可行路线 | 不论条件怎样都顺利完成 |
| 世界受阻与API超时分别发生 | 前者可影响人物解释，后者只影响系统可用性 | 用“今天心情差”掩盖网络失败 |
| 预演两个未来，再提交一个 | 未执行方案不进入回忆和主动分享 | 把预测当经历 |
| 连续多次同一唤醒、提交后崩溃再重启 | 同一事件、作品版本和消息只成立一次 | 重启重新抽结果或重复发表 |
| 1天与30天离线、跨重大节点 | 有界补算；等待边界不被跳过；滞后/未细化可解释 | 回来后凭空经历一整个人生 |
| 用户不回、关闭主动联系、暂停生活 | 不催促；消息限制与生活暂停各自生效 | 每天强凑2条或把沉默写成关系恶化 |
| 用户在聊天中已知道待分享结果 | 不重复开同一新话题；不同新后果仍可续谈 | 只按事件ID去重但语义重复轰炸 |

自然度另做有限盲评：同一人物和预算下比较随机近况、固定脚本、上述项目后果路线，隐藏实现标签；评判是否具体、像同一人物、后果可接续、是否机械重复，保留失败全文。需要跨更多天验证才可声称不乏味；一次成功分享仅证明链路，不证明长期体验。

## 8. 最终取舍与实施入口

首期推荐自建小型活动裁决，复用Gateway、身份与Timeline；采用Concordia的尝试/结算/观察分责、Generative Agents的近未来按需计划、ink的条件与后果保留、EMA的事件意义与应对思路。研究成本进入测试设计，外部框架不进入生产依赖。

不采用四条捷径：让模型每天随口编近况（无法证明连续与失败）；从整部小说逐段播放（没有真正分支与自主行动）；构建全社会每分钟模拟（成本和状态范围失控）；只有固定脚本（可作验收基线，不能证明对新主题泛化）。上述有界路线也不是最终无限世界，必须通过第二个主题/人物的复用及连续日体验来决定扩展。

下一实现片应交付**一个可重启的项目从意图到结果，再到一条真实本地待投递消息**，同时证明无分享、受阻、暂停与等待；不以先造LifeEngine、EmotionManager等空类作为交付。新的模型投影需单独列清：最小人物核心、一个关注/项目、许可行动、少量已提交因果事件；生活不需要整套原文或用户全历史。未获得相应用途授权前，可用固定候选做离线运行语义验证，并明确其不证明模型的人物感。
