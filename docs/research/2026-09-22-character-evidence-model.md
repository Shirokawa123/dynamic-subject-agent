# 多卷资料到起点自我知识：来源与时间表示

2026-09-22；Slice-66 有界调研。只查官方规范，未读取小说、身份或凭据，未调用 Provider。本报告支持 F0–F3 的结构选择，不代表资料已经分析完成。

**结论：复用来源链与时间关系的成熟概念，角色知情必须另外表达。** 资料由谁整理、文字由谁说出、事件发生在谁身上、谁何时知道，是不同问题；把它们压成一条“角色事实”会重新造成本人知识缺失和全知泄漏。

## 官方机制与适用边界

| 主来源 | 已核对的机制 | 本项目复用及不能推出的结论 |
| --- | --- | --- |
| [W3C PROV-DM](https://www.w3.org/TR/prov-dm/#component2)（2013 Recommendation） | 用实体、活动、责任主体和派生关系描述资料来由；可记录修订、引用与主来源 | 将资料版本、证据位置、候选摘要及其修订相连。来源可追溯帮助评估可信度，但不会证明摘要正确、故事属实或角色知道。 |
| [W3C PROV-O](https://www.w3.org/TR/prov-o/#description-qualified-terms)（2013 Recommendation） | qualified relation 将原来的二元关联具体化，允许补充角色、时间等说明 | 借鉴“关系本身也有证据与限定”的结构。`wasAttributedTo` 表示生成责任，不等于小说中的经历归属；`wasInformedBy` 连接活动，不等于一个人物已理解或相信某事实。 |
| [W3C OWL-Time](https://www.w3.org/TR/owl-time/#topology) | 瞬间、区间，以及 before、during、overlaps 等时间关系 | 用相对顺序表达“起点前已发生”“获知在某事件后”，不强填公历日期。它提供时间关系表达，不能自行从回忆语句认定发生时间，更不判断叙述者是否可靠。 |

本轮只借鉴数据概念，不复制代码，不新增 RDF/OWL 推理器、图数据库或依赖，也不宣称符合完整标准。规范是稳定引用来源；当前无需验证某个软件库的维护或运行兼容性。引入实现时仍需单独核实许可证、维护、成本和外发边界。

## 建议的最小语义结构（项目设计推断）

以下是依据上述机制及本项目问题提出的应用设计，不是 W3C 定义的小说模型。

| 层 | 最少要回答的问题 | 不能混同 |
| --- | --- | --- |
| 资料与证据 | 哪个版本/主线、哪段位置、怎样得到这份摘要？ | 资料录入时间不是故事时间；哈希一致不证明解释正确。 |
| 陈述视角 | 谁说的、谁的视角、直述/转述/推测？ | 作者写下的内容不是每个人物都知道；叙述者判断不是当事人自述。 |
| 命题与参与者 | 谁做了什么、与谁是什么关系、哪件作品/职责？ | 同段出现的人名不等于经历主体；关系需方向、对象及生效范围。 |
| 故事时间 | 事件/关系何时成立，相对哪些锚点？ | 后卷首次记述可以是早期经历；篇章排序仅是资料坐标。 |
| 人物认识 | 哪个人在何时，通过何种有证据的途径获知/相信/怀疑什么？ | 事件已发生不代表该角色已知；角色相信不等于客观成立。 |
| 审核与缺口 | 哪些解释已核对、冲突、待查，证据是否足够？ | 未找到资料不等于人物不知道；未选入上下文不等于事实为假。 |

人物及别名需稳定关联，但不要提前合并“读者知道是同一人、角色此时尚未认出的身份”。应分别保留资料侧同一性与角色侧认知。关系也不能只有“哥哥/朋友”标签；至少关联双方、起点状态及依据，避免把他人的亲密关系转移给用户。

每条重要候选都应保留两组独立依据：一组支持命题或经历，另一组支持起点知情判断。亲历、直接听闻、明确回忆可以作为获知途径候选，但需核对具体语境；不能把“参与了事件”实现成无条件全知规则。

## 起点投影与检查建议（项目设计推断）

选择起点时分别审查：故事分支适用 → 命题成立时间 → 目标角色的认识时间/状态 → 当前分享条件。先保留完整认识，再决定本轮说多少。隐私限制不应把“已知但不愿说”改写成“不知道”；重要本人知识缺证时应明确暴露准备缺口，避免靠模型补齐。

至少用下列结构情景检查实际结果，不新增测试类别：

1. 后卷回忆起点前的本人经历：可纳入，但必须有发生及知情依据。
2. 起点前发生、起点后才告知的秘密：客观资料存在，起点本人认识不包含。
3. 他人内心独白或猜测：保留说话者/视角，不转成目标角色自知。
4. 同一关系后来变化：起点只取当时成立状态，后态不覆盖前态。
5. 两处证据冲突、别名身份未揭示、时间未定：保留分歧，不能取最后一条当真。
6. 资料缺失、角色明确不知、角色保密：返回不同审核/披露理由。

现有 EPUB 位置与哈希可继续担当证据定位；本地候选和预览先承接此结构。它不是新的运行时 canonical store，不把模型回复写成来源事实，也不扩大 Provider 载荷。尚待实证的部分是：多卷材料能否填足关键认识、人工判读的一致性、起点投影是否连贯，以及对话能否使用这些结构；仅落下 schema 无法算完成。
