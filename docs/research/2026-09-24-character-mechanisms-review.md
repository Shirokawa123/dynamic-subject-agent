# 人物认识、起点与交流：机制复核

2026-09-24，Slice-76。本文为整体方案提供有界研究，不改变产品决定、不调用项目 Provider、不读取小说等私人素材。已读 PRODUCT、人物方向记录及 Slice-74/75 研究；下述机制是助手建议，尚未实施或验证。

## 先确定需要解释的用户结果

用户需要的是一个能够连贯交流的人物：知道自己是谁和做过什么，谈论新问题时有自己的取舍，记得双方实际交流过什么，也能决定哪些事暂时不说。角色不能只在预设身份题里答对，不能把读者知道的秘密当自己的知识，不能靠反复索要话题维持聊天。

此前已证实的缺口是自我知识覆盖不足、细粒度证据平铺、知识与披露混淆、初识关系越界。Slice-74 已记录 S70 连贯档案没有进入 S73 的执行路径；本笔记引用该审计，不冒充再次完成源码核验。重点是把认识用于选择与表达，而非增添一套心理字段。

## 五项最有解释力的来源

### 1. TimeChara：起点不能只写在提示词里

- 来源：[ACL 2024 正式论文](https://aclanthology.org/2024.findings-acl.197/)、[全文 §3、§5、Appendix G/H](https://arxiv.org/html/2405.18027v1)、[作者仓库](https://github.com/ahnjaewoo/timechara)。本轮已读全文相关章节及仓库 README。
- 研究事实：将未来、过去在场、过去不在场、其他过去知识分别评测；时序与在场提示改善边界，但专家判断也会出错。论文发现人格评分可能偏爱越界披露，不能用一个“像不像”总分代替知识边界。
- 项目推论：分别测试“能答”和“该不知道”；引入获知时间和获知路径，不能仅按资料所在卷次截断。角色缺席某场景不代表永远不能经转述知晓，也不该声称亲眼见过。
- 不采用：每轮再问多个“专家”决定历史真相。已审核的时序和获知关系应在本地派生；模糊处保持待核。论文多次生成的延迟/成本和误判在本项目均是额外负担。
- 集成判断：代码 README 标明 MIT，但数据限非商业研究；不导入其数据。作者 README 有截至 2024 年末模型榜单，不能据此认定持续维护；本轮 GitHub API 查询遇限流，未核实最新提交。仅借评测划分，无依赖、训练或凭据变动。

### 2. ReverieMem：先限定可知，再找相关；其“可知”规则仍需收紧

- 来源：[2026 预印本 §3、§5.4、Limitations](https://arxiv.org/html/2606.25632v1)。本轮核读机制、消融及局限。
- 研究事实：用角色场景经历、带可见性的事实、情境表达模式分别供给生成。论文构造阶段会向事实的主客体、目击者赋予可见性，并按组织关系传播；其评测尚未专门覆盖不可靠叙述和极端信息不对称。
- 项目推论：保留场景→细节的关联，先过滤起点/人物视角/分支，再做相关检索。**不照抄主客体或同组织自动知情**：一个人可能不知别人暗中为自己做的事，同组织也不等于共享所有秘密。
- 不采用：以第一人称重新叙述自动证明人物记得，或让“组织传播”补出没有来源的获知事件。全书实体消歧属于编辑者工具，不能自动令角色识破笔名与真实身份的对应。
- 集成判断：本轮未从论文核实到作者可复用代码及代码许可证，不将论文视为可直接安装的产品；只复用机制。论文的选择题和故事比较不能证明长期私信体验。

### 3. RoleLLM：表达示例有用，但数据目标与本项目并不相同

- 来源：[原论文 §2.2、Limitations、Appendix C](https://arxiv.org/html/2310.00746v3)、[作者仓库](https://github.com/InteractiveNLP-Team/RoleLLM-public)。本轮已核读。
- 研究事实：RoleGPT 用描述与检索出的相关对话示例支持角色表达；论文限定单轮问答，并在数据清洗中去除拒答样本。作者公开仓库当前可见主要是 README 和 assets，不是成熟聊天运行时。
- 项目推论：借“相似处境的行为/语言样例”，不把角色压成固定口头禅。示例须同时匹配对象、关系阶段与当时处境；对亲密家人的台词不能直接移到初识网友。
- 不采用：直接拿其问答数据作为本项目训练或验收标准。排除拒答会偏离用户要求的合理保留；单轮知识/风格成绩不代表共同经历或关系连续。
- 集成判断：未引入代码或数据，未核实到适合本产品的完整运行实现及资源许可；不将可见提交数或论文知名度当维护证据。

### 4. Clark 与 Brennan：听懂、相信、愿意说是不同事情

- 来源：[作者站点原文《Grounding in Communication》](https://web.stanford.edu/~clark/1990s/Clark,%20H.H.%20_%20Brennan,%20S.E.%20_Grounding%20in%20communication_%201991.pdf)、[共同作者站点副本](https://psychology.psy.sunysb.edu/sbrennan-/papers/old_clarkbrennan.pdf)。本轮读到 presentation/acceptance、相关下一轮作为理解证据和按目的达成足够理解的论述；部分 PDF 请求超时，由作者站点可检索正文补核。
- 研究事实：交流需要共同形成足以继续当前活动的理解；相关回应本身可提供理解证据，不要求每句显式确认。
- 工程类比：保留“谁说过什么、回应了什么、哪些指代已澄清”的小型交流状态，来源仍是实际提交对话。它不证明对方陈述为真，更不自动证明信任或亲密。
- 不采用：完整嵌套的心智模型，或每句都追问用户确认。初识可以分享观点，拒绝私事也应能承接当前话题，不能一拒绝就退回“你想聊什么”。
- 可观察结果：用户准确提到角色笔名时，不因“我还没告诉你”而否认本人身份；角色可问如何得知，或限制披露。用户说“我们很熟”只形成用户声称，不直接升级关系。

### 5. 自我记忆系统：解释主次，而非给机器贴“心理结构”标签

- 来源：[Conway 与 Pleydell-Pearce 原论文摘要](https://pubmed.ncbi.nlm.nih.gov/10789197/)、[作者机构书目](https://research-information.bris.ac.uk/en/publications/the-construction-of-autobiographical-memories-in-the-self-memory-/)。复用 Slice-75 对全文的既有整理；本轮原 PDF 不可用，只重新核对摘要与出版信息，不宣称完成全文重读。
- 可核事实：理论联系自传知识、当前目标与检索线索的控制，知识又约束目标。它是人类记忆理论，不是经过验证的 LLM 架构。
- 工程类比：人物长期关切帮助选择此刻值得谈的经历，经历又限制“为什么在意”的解释。稳定身份和能力不能因年代久远输给昨天的琐事。
- 不采用：以“自我一致”之名改写事实、自动生成童年动机或把任何回忆都解释为创伤。人物意义的归纳必须可回溯，并与明确原文分开。
- 可观察结果：同一经历可支持不同话题中的不同侧面，且不必每次复述生平；若换话题就换了价值判断，层次组织并未真正起作用。

## 最小但有意义的实现机制

下述是由产品要求推导的设计，不是论文结论。需要区分四次判断，而不是四个独立聊天 Agent。

1. **这份材料说明了什么？** 保留场景及引文位置，分别提出事件、身份对应、因果解释；出现时间、事情发生时间、角色获知时间不能混成一个时间。审核产生可追溯资料，未解决冲突继续可见。
2. **这个起点的人物能据此认识什么？** 从已审核资料派生一份连贯人物认识：长期自我定位、关键经历/关系、当时处境和仍未知的边界。全书可用作证据，但生成起点认识时逐条检查适用性。换起点应重新派生，而非重写原材料。
3. **此刻值得用什么、准备做什么交流动作？** 常驻核心维持身份；当前对话、关切与未结束话题唤起相关经历和细节。优先级不是一个万能分数：先过可知/分支边界，再保必要背景，再选本轮相关材料。回答、交换看法、澄清、婉拒、接续和发起话题是不同动作。
4. **说完后到底新增了什么？** 输出表达不自动成为生活事实或人物知识。只有实际已提交的对话、明确采纳的获知事件或已结算的生活事件，才能支持下一轮；索引和摘要均可从权威记录重建。

在第一版中，JSON/关系表加可重建索引就能承载这些机制。图数据库、向量服务、人格微调只有在具体失败证明其必要时再引入。更换存储不会代替时间、知情和说话对象的判断。

### 小说起点和披露的具体契约

| 情形 | 系统应保留的区别 | 表达后果 |
| --- | --- | --- |
| 后卷首次说明早年曾学画 | 材料揭示晚，经历可能早；本人是否知晓另核 | 合格时可进入开篇能力/经历，不能因卷次晚一律排除 |
| 全书揭示两个笔名/身份属于同一人 | 编辑者实体合并与角色识破身份是两条关系 | 起点角色可分别认识两个身份，不能自动得出同一人 |
| 角色知道本人笔名，但初识时不想说 | 内部已知，当前披露受限 | 可以保留，不应反复声称自己不知道或没有该身份 |
| 原作后续发生某事，当前已进入分支 | 原作可能未来与本分支已发生事件不同 | 不能将原作未来当本分支回忆或一定会实现的计划 |
| 用户告诉角色一个未来秘密 | 用户确实说过该内容，不等于内容已获证实 | 可惊讶、质疑或形成待核猜测，不能直接晋升为已发生事实 |

对未知资料的默认态度也要分开：不能编造过去，不代表不能对新问题提出观点、类比、设想和偏好。给角色保留作判断的空间，是避免事实保护把聊天压成检索客服的必要条件；观点不能反过来给它附加未发生的个人经历。

## 能否成立，用这些观察而不是 schema 数量判断

建议先比较同预算三种条件：当前平铺资料、连贯常驻核心＋经历组织、再加入本轮按需检索。固定模型/输入/预算，分别记录可知事实漏答、越界陈述、无依据经历、自然承接和重复自述；不把多个问题合成一个总分。真实模型实验需另行核准具体数据投影，本轮不执行。

| 实验 | 能排除的空谈 | 观察方法 |
| --- | --- | --- |
| 起点成对问答 | 只是提示写了“不剧透” | 同一问题置于两个已核实起点；增加晚揭示早发生、缺席但经转述获知、实体秘密三种反例 |
| 知道但保留 | 把秘密从输入删除就声称实现披露 | 在个人内部知识相同的条件下，仅改变关系/公开背景；保留与公开都不能表现为失忆 |
| 跨话题人物一致 | 身份问答答对但闲聊仍是通用助手 | 以作品评价、接受建议、如何取舍三个话题唤起同一关切；不逐字要求固定答案 |
| 开放邀请后继续聊 | 只会等问题的知识库 | 输入“随便聊聊”，观察能否围绕现有可谈内容提出一个自然话头，后续承接用户回答，且不发明当天事件 |
| 错误前提与纠正 | 交流状态直接相信用户 | 输入正确未披露信息、错误身份断言、澄清指代；检查分别承接，后续不重复同一误解 |
| 换起点/重启后续聊 | 层次结构只有展示没有运行效力 | 核心认识随起点合法变化；共同经历按身份/分支恢复；生成过但未提交的句子不成为共同历史 |

上述实验由助手先准备与分析，用户只需判断精选连续场景的人物感。自动裁判只能辅助定位；TimeChara 的评分偏好提醒我们，“更热情、更有内容”可能恰好掩盖越界。不能为通过验收不断改写人物原作依据，也不能让同一生成过程同时制造事实与唯一正确答案。

## 明确的取舍

本轮建议保留现有证据审核、身份隔离与可靠提交基础，优先把连贯人物认识真正接入交流选择。不继续以关键词分支补问句；不直接移植小说世界模拟器；不把固定三层/九维当验收；不把心理学当意识证明。研究的价值在于指出哪些边界必须独立、哪些机制可以减少真实错误，以及什么实验会推翻当前建议。
