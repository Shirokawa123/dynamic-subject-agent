# 产品定义

## 目标

构建本地优先的角色聊天软件，让用户像与网友一样，与一个有可信性格、连续生活和自身意见的虚拟人物长期交流。人物来源可以是小说等材料，也可以是用户原创设定。

这是2026-09-20依据[已确认方向C1–C18](plans/character-chat-direction.md)同步的新目标，不是当前能力清单。dogfood-s51是可复用的工程基线，不能据其既有测试宣称新体验已经实现。

## 核心体验

1. **聊天为主。** 默认自然短消息，需要时可以长聊；角色通过自己的话分享生活。动作旁白为可选模式，设定、来源和诊断不占据主聊天流程。
2. **有来源的人物。** 小说导入后自动分析，用户选择人物、故事起点和世界模式，简明确认设定；可展开依据和修改错误。原创角色支持直接文字设定与问答辅助，用户内容和助手补充分开确认。
3. **连贯的自我知识与角色视野。** 角色需要认识自己的生平、关系、能力、工作、在意之事和当前处境，不能只有少数身份字段或为测试准备的问答。多卷甚至全套可作为资料；角色只使用当前故事阶段适用、自己知情的信息。后卷揭示的早期背景需核对时间与知情，未来事件及后期成长不能无条件回填起点；知道、不确定与暂不愿披露分别处理。
4. **连续的虚构生活。** 默认用户离线时日常继续推进，允许暂停和调整速度；角色有已经发生、能够接续的虚构经历。时间推进方式未定，不能把现实过去多久直接当作某件事已经发生的证据。
5. **可选择的故事模式。** 首版优先原作世界，默认保留既往经历并允许此后分支，另提供严格原剧情模式；进入新世界保留为后续方向。重大节点默认先给用户参与机会，长期缺席时等待；也可选择完全自主推进。
6. **有分寸的主动联系。** 有值得分享的事情才主动联系，默认每天最多两次新话题，可调整或关闭；上限不是配额，进行中的聊天不计入，不因未回复持续催促。角色可以有事在忙，具体机制应避免制造漫长等待。
7. **关系来自相处。** 首次体验从初次相识开始，用户保持现实身份，角色生活在原作世界，双方知道跨世界聊天渠道存在；角色起初不预知自己是用户看过的作品人物。信任与交流方式从后续经历形成。
8. **角色可以有所保留。** 可以不同意建议、拒绝话题或不愿分享，理由来自性格、经历和关系；不以随机对抗或责怪用户制造存在感。

## 首份原型与阶段验收

首个参照是小说版《埃罗芒阿老师》的和泉纱雾，起点在第一卷开篇附近，具体段落须用材料核实。已收到14份EPUB，完成本地清点、结构定位及少量起点人物依据核对；这不代表完整人物提取或整套模型分析获准。

原型展示：选择人物/起点→初次聊天→隔天生活分享→接续前一天话题→表达一次不同意见。评价人物感、生活连续性和交流自然度，助手负责准备演示，用户判断感觉。预设台词、模拟时间与真正运行的能力必须标明；原型不等于生产实现。

新方向的正式可用版本需证明：

- 从材料/原创设定到可核对的人物创建成立，当前角色视野不会自动获得未来剧情。
- 对话能接续共同经历，角色的新生活事件有清楚归属且跨重启一致。
- 主动消息来自可分享的事件，遵守频率、暂停、未回复和重复投递约束。
- 首个五情景通过用户体验反馈，并完成对应可靠性验证；无已知静默丢写或身份混用。
- 模型用途、数据范围及迁移有明确授权；用户能理解设定、暂停、来源及失败状态。

上述条件尚未全部实现；旧v1的927项测试只继续守护其适用的基础行为。文件保存和目标面板保留为辅助能力，不替代新体验的验收。

## 保留的原则与非目标

身份隔离、单一canonical Timeline和唯一写者、原子Publication/恢复、模型只提议/Python裁决、最小授权投影及安全凭据管理继续保留。用户自己的记忆/目标、角色的虚构经历、原作事实和实际共同聊天不得混写。虚构世界中的事件不能冒称现实世界的执行结果。

不声称意识，不模拟用户，不把系统做成多Agent委员会；不默认引入自动人格重写、Reflection或完整多人物社会模拟。动画视频导入与可选世界模式属于总体方向，完整实现不挤入首份小说人物原型。

角色生活与主动联系已纳入产品目标，但新的模型数据用途、后台运行/通知及具体机制仍须单独落实。未授权删除、旧身份不可逆迁移、任意工具、对外执行或新credential用途。详细阶段与旧版契约见[ARCHITECTURE](ARCHITECTURE.md)。
